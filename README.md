## 三、怎么跑

### 1. 打牌时：面板 + 影子记录

```powershell
.venv/Scripts/python.exe -m guandan.launcher
```

一条命令做完四件事，**任何一条失败路径都不许留下断网**：
装 mitmproxy 证书 → 起抓包（带看门狗）→ 等代理真的连通 → 开面板；退出时全部还原。

| 参数 | 用途 |
|---|---|
| `--dry-run` | 只检查环境，不动系统代理 |
| `--no-panel` | 只起抓包，不开面板（调链路用） |
| `--no-advice` | 关掉影子模式（不加载权重） |
| `--no-show-advice` | 算建议但不显示（记录里如实写 `advice_shown:false`） |
| `--level N` | 手输级别（日志读不到时兜底） |
| `--console` | 用终端版面板 |
| `--selftest N` | 走 N 局把流程走顺再退出（演示前排练还原路径） |
| `--yes` | 跳过确认 |

启动时会自己报加载了哪份权重 —— 这一行是判断「换没换源」的唯一依据：

```
影子模式就绪 —— 模型：guandan/models/best.pt（210,016 局）
```

### 3. 训练

```powershell
$env:GUANDAN_DEVICE="cpu"      # ⚠️ 实测最优，不是将就：这个循环以 Python 为主，上 GPU 只抢显存
.venv/Scripts/python.exe -u -m guandan.rl.selfplay 32400 `
  --init models/best.pt `
  --opp-kind rule --opp-mix 0.5 --workers 2 `
  --out-dir runs/R12 *> runs/R12.log
```

第一个位置参数是**秒数**（32400 = 9 小时）。常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--init <ckpt>` | 无 | 热启动。**ε 起点自动压到 0.3**（`--eps-start` 可覆盖） |
| `--opp-kind {greedy,rule}` | `greedy` | 固定对手：贪心（弱、已饱和）或规则式（像人，**推荐**） |
| `--opp-mix F` | `0.5` | 每局以 F 的概率把一个队换成固定对手 |
| `--workers N` | `1` | 多进程自对弈 |
| `--out-dir <dir>` | `runs/<时间戳>` | 两臂必须分开，否则后跑的覆盖 `best.pt` |
| `--eps-games G` | `250000` | ε 退火到 0.1 所需的**局数**。**跑短实验一定调小** |
| `--buffer N` | `50000` | replay 容量（局） |
| `--algo {dmc,pg}` | `dmc` | ⚠️ `pg`（REINFORCE）**会塌**，别拿它跑长训练 |
| `--eval-rule-games N` | 同 `--eval-games` | **规则式那把尺子**跑多少局；`0` = 不跑。规则式慢（200 局约 10 秒），量吞吐的短跑要关掉 |
| `--eval-games N` | `200` | 训练内评测局数。⚠️ **`best.pt` 就是按这个读数挑的**：200 局的 sd ≈ 2pp，与一代进步（~3pp）同量级 ⇒ 想挑得稳就调大（代价：每次评测更慢） |
| `--eval-every N` | `10000` | 每多少局评测一次（同时决定曲线/快照点的密度）。短臂要调小才看得到曲线 |
| `--mate-mix F` | `0.0` | **A3 队友多样性**：以 F 的概率把**学习队的搭档**换成 `--opp-kind` 的固定策略，那一局只剩一个座位学。**只在有固定对手的局里生效** ⇒ 实际剂量 = `opp_mix × F` |
| `--greedy-share F` | `0.8` | 老二分里「贪心」的份额（其余是**随机**对手）。`1.0` = 关掉随机那一路 |

**评测输出长这样**（每 `--eval-games` 局一次；`vs 规则式` 是**主尺子**）：

```
     >> 评测 @   10000 局：vs 随机 99.0%   vs 贪心 95.5%   vs 规则式 70.5%
末次：vs 随机 99.1%   vs 贪心 95.5% / 94.0%（两次，差 1.5% —— 200 局的噪声约 ±2%）
      vs 规则式 70.5% / 69.5%（两次，差 1.0%，**与上面同一副牌**） ← **主尺子**
曲线（局数:vs随机/vs贪心/vs规则式）：10k:99%/96%/71%  20k:99%/95%/70%
```

⚠️ 这三个数**共用同一个 `--eval-games`**，所以互相可比；但跟 `tools.ruler` 那套
（多臂 × 6 种子配对 × 400 局）**不是一个口径**，别把训练内的数直接当台账数字引用。
⚠️ **退出码仍按 `vs 贪心 ≥ 55%`**（与历史跑可比）；但 **`best.pt` 现在按 `vs 规则式` 挑**
—— 老口径按训练内 200 局 `vs 贪心` 挑，而噪声 ±2pp 与一代的进步（~3pp）同量级，
等于在抽签。训练时会打一行 `↑ 刷新最好（vs 规则式 …）-> best.pt`，口径也记进权重
（`best_metric`）。要**跨臂比较**或挑最终部署件，仍请用 `tools.ruler`。

**三条训练纪律（都是踩出来的）**

1. **绝不并发两条臂** —— 一条约 4.8 GB，这台机器只够一条（并发过、打爆过）。
2. **热启动短于 ~50 万局基本白跑** —— ε 从 0.3 退到 0.1 要 25 万局，大半预算花在探索上。
   实测：54 万局的续训只值 +0.7pp（测不出来），78 万局才值 +3.8pp。
3. **`Ctrl-C` 是安全的**（走收尾逻辑）；快照每 2 万局一份，**最多丢 2 万局**。
   恢复只需 `--init` 指到最新快照，但**局数计数器会重启**。
4. ⚠️ **热启动不要把 ε 拉回 0.3**（2026-09-30 夜实测，2 小时/条臂，同预算同种子）：
   | ε 轨迹 | 与热启动起点的差 |
   |---|---|
   | 0.30 → 0.13（**默认退火 25 万局**） | **−3.25pp（t=−3.09，成立）** |
   | 0.30 → 0.10（`--eps-games 100000`） | +0.25pp / best **+1.42pp**（12 种子 **+2.02pp**） |
   | **恒 0.10**（`--eps-start 0.1 --eps-games 1`） | −0.12pp / best +0.46pp |
   **机制**：这个游戏里"随机一手"极贵 —— 给权重在**评测**里加 13% 随机就是 **−11.3pp**
   （`tools/eps_noise.py`；28% 是 −23.8pp）。高 ε 阶段生成的数据里全是这种手
   ⇒ **臂在拿被污染的数据当老师**，练得越久越偏。
   ⇒ 续训**要么**把退火缩到 10 万局，**要么**直接从 0.1 起步不退火；
   两条路都在 **10~12.5 万局**就追平了 21 万局的起点（**样本效率约 2×**）。
5. ⚠️ **"多条独立的短臂 + 权重平均" 比 "一条长臂" 强**（2026-10-01 夜，**零训练成本**）：

   ```powershell
   # 把若干存档平均成一个（确定性成员表，见 tools/make_soup.py）
   .venv/Scripts/python.exe -m tools.make_soup --out runs/ab/soups/soup.pt
   # 换源前照例用尺子配对复核（见 §四）
   .venv/Scripts/python.exe -m tools.ruler models/best_r11_backup.pt runs/ab/soups/soup.pt `
       --base models/best_r11_backup.pt --seeds 1002,...,1017 --games 300
   ```

   | 权重 | 相对 R11（配对，16 种子 × 300 局） |
   |---|---|
   | 最好的**单件** | +1.44pp（t=1.60） |
   | 3 个成员平均 | +2.00pp（t=2.32） |
   | 5 个成员平均 | +2.58pp（t=3.33）；**独立种子集复核 +3.54pp（t=4.44）** |
   | **9 个成员平均（现役）** | **+2.62pp（t=3.98）** |
   | 21 个成员（混进"中毒 ε"轨迹的快照） | +2.54pp ⇒ **反而变差** |

   **机制**：成员越多越好 = **方差缩减**的特征（不是选点运气）；权重平均是**确定函数**
   ⇒ **没有选择偏差**（这点与"挑一个最好的快照"有本质区别，后者自带 ~0.6pp 偏差）。
   **纪律**：① 成员要来自**配方干净**的臂（别把已知有问题的臂的快照混进去）；
   ② 算力应该花在**多条独立短臂**上，而不是一条长臂 ——
   **3 小时 / 24.1 万局的长臂末尾件与 R11 打平（+0.00pp）**，它自己的中段最好（16 万局）才有 +1.97pp
   ⇒ **超过 ~16 万局在这一配方下是浪费**；把那 3 小时拆成两条短臂再平均，收益更实在。

## 四、权重怎么换（只有一条路，而且看得见）

回滚 = 一条 `Copy-Item`）。⚠️ t 未到我预登记的 2.5，属于"很可能更好"而不是"已确证"。
**2026-10-01 夜的换源记录（第三次 / 最终）**：`runs/ab/soups/soupE.pt` → `models/best.pt`
（依据：**12 种子 × 300 局配对 +3.00pp vs R11，t=3.59**；11 个成员的**确定性并集**平均，

**2026-10-01 夜的换源记录（第二次）**：`runs/ab/soups/soupB.pt` → `models/best.pt`
（依据：**16 种子 × 300 局配对 +2.62pp vs R11，t=3.98**；它是 **9 个存档的权重平均**，
用 `tools/make_soup.py` 的确定性成员表重建即可复现；成员 = R11 + O1/O2b/O3b/O4 的 best/last。

## 七、已知的坑与下一步

### 实机反馈：**白炸 / 白用万能牌**（2026-10-01 用户实测）

用户原话：①「有牌可以压制的情况下会使用炸弹进行压制」；
②「炸个 8888 就行了，但他会用万能牌构造成五个 8 去炸」。

**量出来的**（`tools/mistake_profile.py`，现役权重，300 局；判定与战报/尺子共用
`rl/eval.py` 里那一份口径）：

| | 白炸（有普通牌能压却出炸） | 白用万能牌 | 万能牌放大炸弹 |
|---|---|---|---|
| 模型 | **7.4%**（411/5557） | 3.1% | 2.4% |
| **规则式（参照）** | **0.0%**（0/4984） | 2.8% | 2.3% |

⇒ 第①条**确认、而且量级很大**（规则式结构上不犯，模型每 13 次能压的牌里就有 1 次用炸）；
第②条与规则式**基本持平**。

**为什么会这样（两条，都别怪"训练不够"）**：
1. **标签里没有炸弹/万能牌的价格** —— DMC 标签只有终局回报，而一局 ~132 个决策点共享它；
2. **脚本对手不惩罚浪费** —— 实测（`tools/tidy_screen.py`，配对）：
   normal −2.11pp（t=−3.33）、bomb −2.81pp、**hold（最会存炸的）−1.06pp（分辨不出）**
   ⇒ 这三个对手**都不为"少炸"付钱**，所以模型学到的"该炸就炸"在这把尺子上是**对的**。

**两个修法（都已实现）**：

| 修法 | 怎么用 | 代价 / 判据 |
|---|---|---|
| **推理侧"擦浪费"**（**推荐开**） | ⭐ **推荐 `$env:GUANDAN_TIDY="margin:0.25"`** —— 只在网络自己**犹豫**（首选与最省候选之差 ≤0.25）时才换成"最省资源"的那一手（字典序：不用炸弹 > 用炸弹；不用万能牌 > 用万能牌），同级内仍按网络 Q 挑 | **又省又赚**：白炸 6.9%→**2.8%**，配对胜率 **+1.22pp（t=2.04，独立种子）**。老档 `GUANDAN_TIDY=1`（硬替换）能压到 0.0% 但要 **−2.11pp**（t=−3.33） |
| **训练侧动作计价** | `--bomb-cost λ`（既有）+ **`--wild-cost λ`**（新增）：每用一颗炸/一张逢人配，从这一步起的标签少 λ | 默认 0 = 老行为；把"少用资源"从终局回报之外**显式**教给模型 —— 这是脚本对手惩罚不到的那一维 |

**代价训练的实验结果（2026-10-02，`plans/2026-10-02-bomb-wild-cost.md`）**：
从 R11 起、干净 ε、6000 秒的一条臂带 `--bomb-cost 0.2 --wild-cost 0.4`，
与同配方无代价的对照臂比 ⇒ **三项判据全过**：

| | 代价臂 W1 | 对照 O3b |
|---|---|---|
| 白炸率 | **4.9%** | 7.3% |
| 用炸手数（300 局） | 747 | 858 |
| normal（配对） | **+1.17pp** | — |
| hold（配对） | **+2.06pp** | — |

⇒ **代价训练是严格帕累托改进**（浪费更少、胜率更高）。⚠️ 但**权重平均会稀释它**：
W1 并进 13 成员的 soup 后白炸率回到 **6.9%**（现役 soupG）。
λ 再加倍（W2：0.4/0.8）能把白炸压到 **2.7%**，但要付 ~1.5pp 胜率 ⇒ **过了拐点，不建议再加**。

⚠️ **2026-10-02 的重要修正（联赛尺子）**：上面那句"代价 ~2.1pp"是**对着脚本规则式**量的，
而它**不惩罚资源浪费**（自己从不炸、也不会因为你浪费而变强）⇒ 它给"乱炸"发了奖励 ✗。
换成**同强度对手**（soupG 打自己，8 种子 × 800 局）：

| 对手 | 原样 | 擦浪费（margin=0.25） |
|---|---|---|
| 脚本规则式 | 73.9% | 71.6%（**−2.11pp**）✗ |
| **soupG 自己** | 49.9% | **51.7%（+1.80pp，t=+3.36）** ✓，且白炸 6.9%→**3.3%** |

⇒ **`GUANDAN_TIDY=margin:0.25` 不是取舍，是免费收益** ✓
⇒ **凡涉及资源/信息纪律的改动，两把尺子一起看；方向冲突时信联赛尺子**。

**结论（推荐配置）**：权重用 **soupG**（normal +3.47pp / hold +4.39pp vs R11），
面板开 **`$env:GUANDAN_TIDY="margin:0.25"`** —— 白炸 6.9% → **2.8%**，
而**配对胜率还 +1.22pp**（独立种子复核）。
机制：Q 差在噪声量级（≤0.25）的炸弹/万能牌选择本来就是**抛硬币**，换成"省资源"的偏置反而更准
—— 这与"代价训练同时降浪费又涨胜率"是同一个发现的两面：**资源守恒在这个游戏里是个好先验**。

⚠️ 三处**真 bug** 是这一轮踩出来的（都留了测试）：把"过"当成最省资源（该炸变成过牌）、
丢掉"桌上有牌要压"这个前提（连主动出炸都被降级）、`worker_cfg` 签名漏了 `wild_cost`。

### 已**关闭**的方向（2026-10-01 夜量过，别再投算力）

| 方向 | 为什么关掉 |
|---|---|
| **推理时搜索**（一步/rollout/带符号） | 三种变体 **−17.8 / −32.5 / −70.4pp**。机制：Q 的**量级**（±2.5）远大于它的**动作差**（0.1），跨状态搬值 = 把噪声放大成决策 |
| **残局单独造标签**（确定性 rollout 蒸馏） | ① 标签自身两半一致率只有 **80%**；② 网络对标签的成对准确率**微调前就有 0.7632**（贴着天花板），微调后**掉到 0.6447** ⇒ **没有可蒸馏的增量**。那个"22% 的分歧点 +0.36 点"是 rollout 专家自己的噪声 |

| **优化规则式的逻辑** | 反事实解剖（`tools/rule_autopsy.py`，把规则式当学生）：分歧点占 **41.4%**，但"听网络"的**单步因果价值 = +0.000 点（t=0.00）** ⇒ 它的弱不是"某几步选错"，而是**整局轨迹**；决策层面**没有余量**可捞（它当尺子更不能乱改） |
| **在脚本对手上继续刷分** | 尺子已饱和（各臂都在 70~73%），且"加成员到 9 个之后"边际趋零 ⇒ 换目标/换表征才是剩下的路 |
