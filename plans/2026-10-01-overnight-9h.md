## 五、点⑤ **PPO 信任域**（实现 + 预登记，**起臂之前写下**）

### 5.1 为什么 PG 会塌（实现层面的诊断）

`_pg_step` **只用一批数据更新一次** ⇒ 重要性比恒等于 1 ⇒ **"信任域"这件事在它那里根本不存在**；
熵奖励只是软约束（β 从 0.01 扫到 0.1 都治不了，台账里记着）。
PPO 的做法：同一批数据走 `--ppo-epochs`（默认 **4**）轮小批，每轮把 `π_new/π_old`
**裁到 [1−ε, 1+ε]**（ε = `--ppo-clip`，默认 **0.2**），超半径的梯度归零。

**行为策略的 log-prob 当场算**（更新前那一刻的网络就是行为策略，PG 是 on-policy）
⇒ 不用改 worker 的记录格式。`--algo ppo` 是**新增算法名**，PG 一行没动（老结果仍可比）。

⚠️ 一个我第一版搞错、值得记的点：**PPO 与 PG 的损失值本来就不该相等**
（`−lp·A` vs `−ratio·A`，相差常数 `lp_old·A`）；但在 `ratio≡1` 处
`∇ratio = ratio·∇log π = ∇log π` ⇒ **梯度完全相同**。
所以不变量测试钉的是**梯度**（`tests/test_ppo.py::test_one_epoch_without_clip_matches_pg_gradient`）。

### 5.2 预登记判据

| 项 | 判据 |
|---|---|
| **不塌** | 45 分钟（2700 秒）内**熵守门不触发**（PG 就是被它逮到的） |
| 强度 | 与同预算的 DMC 干净 ε 臂对照：≥ +1pp 且 t ≥ 2.5 |
| 配方 | `--algo ppo --init models/best_r11_backup.pt --opp-kind rule --opp-mix 0.5 --workers 2 --eps-start 0.1 --eps-games 1` |

⇒ 起臂：`runs/ab/P1_ppo`（2700 秒）。

### 4.6 点④ **收口结论：残局没有可蒸馏的增量**（三次尝试 + 两个关键量）

| 尝试 | 结果 |
|---|---|
| ① 绝对回报回归（694 条，M=8） | +1.22pp（12 种子）→ **独立复核 +0.10pp** ✗ |
| ② 绝对回报回归（1542 条，M=24） | +0.79pp（16 种子）→ **独立复核 +0.23pp** ✗ |
| ③ **成对排序损失**（1542 条、按组切分、10 轮） | 成对准确率 **0.7632 → 0.6447**（**越练越差**）✗ |

两个关键量（都在 `tools/endgame_label_noise.py` / `endgame_finetune.py` 里量到）：

- **标签自身的一致性**：把 24 次采样劈两半，"哪个候选更好"的一致率 **80.0%**。
- **网络对标签的成对准确率（微调前）**：**0.7632** ⇒ **已经贴着标签质量的天花板**。

⇒ 微调只能学到噪声（0.76 → 0.64）。所以 `tools/endgame_probe.py` 那个
"22% 的分歧点上 +0.36 点（t=2.39）"**不是网络的短板**，而是**rollout 专家自己的噪声**
（它判定的"更好"并不真的更好）。
⇒ **点④ 结论：不要为残局单独造标签**（这条方向到此为止，别再投算力）。

**顺带被否掉的一个实现猜想**：我原以为"候选之间共用同一批确定性采样"（公共随机数）
能降噪 —— 实测 **0.181 点 vs 独立采样 0.171 点，没有降噪**（一致率 80.0% vs 82.5%）✗
（代码保留，但它不是收益来源；别把它当成"已优化的点"）。

### 4.7 点⑤ **PPO**：实现正确，但**代价 8× ⇒ 在墙钟预算下不可行**

| 项 | 数 |
|---|---|
| 不塌（2700 秒烟测） | **没触发熵守门、没崩** ✓（但只跑到 ~7 千局，见下） |
| 吞吐 | **2.5 局/秒** 对 DMC 的 **~20 局/秒** ⇒ **约 8× 开销**（4 轮 × 小批更新） |
| 损失量级 | `loss=-0.070  H=0.558` ✓ 是真正的 PPO 损失（DMC 是 3.x） |

⇒ 本项目的所有结论都活在**按墙钟算预算**的坐标系里（"2 小时一条臂"）。
PPO 在这个预算下只能跑 1/8 的局数 ⇒ **即使它不塌，也不具竞争力**：
按 8× 开销折算，要跑到与 DMC 臂同等局数需要 16 小时。
⇒ **点⑤ 结论：实现留档（`--algo ppo`，含梯度等价不变量测试），但不要用它跑正式臂。**

**⚠️ 这一节还抓到一个真 bug（值得记）**：`--algo ppo` 第一版**静默走了 DMC** ——
多进程那条路的**上层**分支写的是 `if algo == "pg": ... else: <DMC>`，
臂名与日志头都写着 PPO。**唯一的线索是日志里的 loss 量级**（PPO 该是 O(1)，它却是 3.8）。
👉 处理：分派收敛成唯一的 `_rl_step()`，并加测试
`tests/test_ppo.py::test_rl_step_dispatch_covers_ppo` 钉住；跑成 DMC 的那条臂已删除。

### 4.8 点⑤ 烟测**结果：PPO 也塌，而且比 PG 更快** —— 但报错给出了真根因

烟测（2700 秒、`--algo ppo --eps-start 0.1 --eps-games 1`、从 R11 起）在 **1740 个决策点**
就被熵守门逮住：

```
RuntimeError: 策略熵塌了：逐点「熵/均匀熵」的中位=0.006633 < 0.05（1740 个决策点）
```

⇒ **裁剪没有救它**（我原本的假设"PG 塌是因为没有信任域"**被证否**）。

**真正的根因（报错与代码一起指向的）**：这条把 **Q 当 logits** 用，而**没有任何东西管它的尺度** ——
DMC 路径有 MSE 回归把 Q 钉在回报尺度（±3）上，所以 `check_q_scale` 有效；
actor 路径只把"采样到的那一手"的 logit 往上推，**尺度单调漂移** ⇒ softmax 饱和 ⇒ 熵塌。
信任域管的是"一步走多远"，管不了"尺度往哪漂"。

### 4.9 点⑤ 的修法与**预登记判据**（起臂之前写下）

给 actor 路径加一项小系数的 **MC 值回归当尺度锚**（就是 DMC 的目标，数据现成）：
`--ppo-value-coef`（默认 0 = 老行为）。

| 判据 | 值 |
|---|---|
| **诊断成立** | 带锚（`--ppo-value-coef 0.2`）的 20 分钟烟测里**熵守门不触发**（对照：不带锚 1740 个决策点就塌） |
| 附带 | 吞吐仍然 ~2.5 局/秒 ⇒ **即便修好，8× 开销也让它在本项目的墙钟预算下不划算**（结论不变） |

⚠️ 起臂时机：**等 F3 长臂跑完再起**（纪律：绝不并发两条训练臂）。

| 「听网络更好」的比例 | 19.5% |
| 分阶段 | 开局 +0.035 / 中盘 +0.208 / 残局 **−0.273** 点 |

### 结论（**回答用户那个问题**）

- **规则式的弱点不是"某几步选错"**：即便把它的选择换成网络的（网络胜率是它的 2.4 倍），
  **单步因果价值 = 0**（t=0.00，CI 约 ±0.28 点）⇒ 网络的强不是"每步更准"，
  而是**整局轨迹更优**（配合/节奏/规划这类跨多步的东西）。
- ⇒ **优化规则式的逻辑在"决策层面"没有可捞的余量**；作为**尺子**改它只会作废历史数字
  （本仓库 2026-09-29 已经吃过一次）。⇒ **不建议**把它当成涨分手段。
- 这与前一夜"让网络听规则式 ⇒ Δ≈0"是**同一件事的两面**：
  两者的**局部**可替换性很高，但**全局**强度差 2.4 倍。

⚠️ 分辨率：n=200、sd 2.05 ⇒ 小于 ~0.3 点的单步效应量不出来（所以只能说"没有大的局部余量"）。

### 7.2 这一夜真正学到的（按重要性）

1. **权重平均（soup）是零训练成本的免费增益**，机制是方差缩减，且**没有选择偏差**
   （与"挑一个最好的快照"有本质区别 —— 后者实测带 ~0.6pp 偏差）。
2. **策略梯度那条路塌陷的真根因不是"没有信任域"，是 Q 的尺度没有锚** ——
   PPO 的裁剪没能救它（1740 个决策点就塌）；加 `--ppo-value-coef` 尺度锚是正解（见 §4.9 的烟测）。
3. **残局没有可蒸馏的增量**：网络对 rollout 标签的成对准确率微调前就 0.7632（天花板 0.80），
   微调后掉到 0.6447 ⇒ 那一堆"残局正信号"是不显著的噪声。
4. **规则式的弱不是"某几步选错"**：反事实"听网络"的单步价值 = **0.000 点（t=0.00）**
   ⇒ 想涨分就别去改它的逻辑。
5. **观测/日志量级是排错的第一线索**：`--algo ppo` 跑成 DMC 那次，唯一的线索就是
   日志里的 loss 量级（PPO 该 O(1)，却是 3.8 的 DMC 损失）。分派已收敛成一处并有测试。

## 八、现役 soupB 的独立佐证（**不是**主尺子那一把尺子）

主尺子的 +2.62pp 有可能只是"尺子假象"，所以再用两套独立读数核一遍：

| 读数（300 局） | soupB（现役） | R11 |
|---|---|---|
| 动作边际中位 | 0.101 | 0.100 |
| 风格尺子 `bomb − normal` | +14.00pp（t=4.78） | +13.67pp（t=30.99） |
| 风格尺子 `hold − normal` | **+1.50pp**（t=1.44） | **−2.50pp**（t=−8.66，成立）⇒ **弱点被修平** |
| 结构：2-4 胶着输 | **4.3%** | 4.8% |
| 结构：被双上 | **8.1%** | 9.5% |
| 结构：残局转化（有出牌权） | **68.7%** | 67.1% |
| 结构：与规则式着法一致率 | 49.2% | 47.5% |

⇒ 三套独立读数方向一致（更少胶着输、更少被打崩、残局转化略好），
**说明这次提升不是主尺子的假象** ✓（300 局的噪声约 ±2pp，所以这只是"方向佐证"，不是新证据）。

⚠️ 注意一处**表面矛盾**（要写清楚）：结构工具仍在提示"残局是短板"（有出牌权只有 68.7% 赢），
而 §4.6 我又结论"残局没有可蒸馏的增量"。两者不矛盾：
**残局转化率低 ≠ 残局决策错** —— 进残局时的**牌面/名次**本身就决定了大部分结果
（与 §六 的"规则式的弱不是某几步选错"是同一个发现的两面）。

## 九、F3 长臂（3 小时、**24.1 万局**、干净 ε）：**平台被确认，而且"更多局数"反而无益**

| 权重 | vs 规则式（12 种子 × 300 局配对） | 相对 R11 |
|---|---|---|
| `F3_long/best.pt`（16 万局处，训练内挑出） | 72.6% | **+1.97pp**（t=2.51） |
| **`F3_long/last.pt`（24.1 万局，末尾）** | **70.7%** | **+0.00pp（t=0.00）** |
| 现役 `soupB`（9 成员） | — | +1.94pp（t=2.70） |
| **`soupE`（11 成员 = soupB 的成员 + F3 best/last）** | **73.7%** | **+3.00pp（sd 2.9pp，t=3.59）** ✓ |

训练内曲线（`vs 规则式`）：40k:73% → 80k:72% → 120k:72% → 160k:73% → 200k:72% → **240k:69%**。

⇒ 两条结论：
1. **在修好的 ε 配方下，"更多局数"不再带来增益** —— 24 万局的末尾件与 R11 **打平**，
   而它自己的中段最好（16 万局）还有 +1.97pp ⇒ **训练超过 ~16 万局在这一配方下是浪费**
   （与昨晚 O4"在最好快照上继续练反而 −1.4pp"互相印证）。
2. **"多条短臂 + 权重平均"仍然是唯一的正收益来源**：把 F3 并进 soup 后拿到本项目最强读数
   **+3.00pp（t=3.59）**，且它是**确定性规则**的产物（并集），不是挑出来的。
