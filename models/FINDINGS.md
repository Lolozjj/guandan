## 模型信息

两个模型都是 **52 类**，命名格式 `<点数><花色>`：

```
2S 3S ... 10S JS QS KS AS    ← ♠ Spade
2C ... AC                     ← ♣ Club
2D ... AD                     ← ♦ Diamond
2H ... AH                     ← ♥ Heart
```

**没有大小王**（大小王不在标准扑克牌体系内）。

与本项目 `dataset/classes.txt` 的映射关系——花色字母 `C/D/H/S` 完全一致，仅顺序相反：

| 预训练模型 | 本项目 | 说明 |
|---|---|---|
| `2S` | `S2` | 点数在前 vs 花色在前 |
| `10H` | `HT` | 10 写作 `10` vs `T` |
| — | `JOKER_S` | **无对应** |
| — | `JOKER_B` | **无对应** |

## 训练背景（来自 `args.yaml` + `results.csv`）

```
data     : /content/Playing-Cards-4/data.yaml   (Roboflow 导出，Colab 训练)
model    : yolo11n.pt
epochs   : 30
imgsz    : 640
degrees  : 0.0        ← 没开旋转增强
fliplr   : 0.5
mAP50    : 0.995      ← 第 5 轮就饱和
mAP50-95 : 0.823
```

**mAP50 = 0.995 且混淆矩阵零混淆**，这在真实牌面检测里不可能出现——真实场景必然有 ♠/♣、♥/♦ 混淆。这本身就说明数据集过于简单。

## 训练数据的样子

`train_batch0.jpg` 显示：把某种特定设计的牌面**贴到随机背景纹理上**（绿棕榈叶、波点、木纹、大理石、织物）。

两个要点：

1. **标注框打在角标上**，不是整张牌 → 与本项目方案一致，这是独立的第三方印证
2. 牌是**大尺寸、居中**的 → 与掼蛋截图里密集叠放的小牌尺度差异巨大

## 失败原因

用两张真实照片测试（土耳其语扑克识别 Web 应用的摄像头实拍，复杂背景 + 真人 + 旋转的牌）：

| 测试 | 结果 |
|---|---|
| 全图 `imgsz=640`，conf 从 0.25 降到 0.01 | 0 框 |
| 全图 `imgsz=1280` | 0 框 |
| 裁出牌区域 + 放大 2× | 0 框 |
| 旋转 0/90/180/270 度 | 全 0 框 |
| **在模型自己的 `train_batch0.jpg` 上** | **正常检出 `3C QD 10C QC`** |

最后一行是关键：**权重是好的**，在它自己的数据域内工作正常。所以失败原因不是模型损坏，而是：

**域差异（domain gap）**——训练用的牌面设计与真实目标完全不同。模型学到的"角标长什么样"这个特征在这里完全不适用。

因为基准（0°）就是零检出，**旋转鲁棒性无法验证**，`degrees: 0.0` 的影响有待后续实验确认。

## 对项目的影响

1. **方向确认**：角标检测是对的路子，公开数据集也这么做
2. **掼蛋自有数据是必需项**，不是"效果不好再补"的优化项
3. **不要从这些权重微调起步**——它们的牌面先验不适用于掼蛋。应该从 `yolo11n.pt`（COCO）起步，或从掼蛋合成数据训起
4. **训练时必须开 `degrees`**（掼蛋四家手牌朝向不同）
