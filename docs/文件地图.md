# 文件地图 —— 每个目录/文件是干什么的

> 2026-09-28 写，**2026-09-29 更新**。
> **一句话答案：跑面板时加载的是 `runs/rl/20260929-r8rule/best.pt`**（78 万局那版，
> 拿它当固定对手练出来的）。上一版 `20260926-1407/best.pt`（144 万局）**保留着没删**，
> 想换回去就用 `GUANDAN_WEIGHTS` 指过去。
>
> ⚠️ **启动时控制台会自己报加载了哪一份**（`影子模式就绪 —— 模型：…（N 局）`）——
> 面板挑权重是「按修改时间挑最新的 `runs/rl/*/best.pt`」，不报就分不出换没换源。
> 想知道「哪个目录干什么」看 §三；想逐个文件查看 §四。

## 一、面板用的是哪个模型 —— 全仓库只有一处口径

决定这件事的**只有一处代码**：`net/advise.py::resolve_weights()`

```python
return path or os.environ.get("GUANDAN_WEIGHTS") or newest_weights()
```

而 `newest_weights()` 就是：**`runs/rl/*/best.pt` 里「修改时间最新」的那一个**。

现在（2026-09-28 实测）磁盘上所有 `best.pt`：

| `runs/rl/` 下的存档 | 修改时间 | 是什么 | 会被加载吗 |
|---|---|---|---|
| **`20260929-r8rule/best.pt`** | 09-29 21:0x | 78 万局；规则式打它 **35.1%**（打上一版 R7 是 39.2%） | ✅ **就是它** |
| `20260929-r7rule/best.pt` | 09-29 17:07 | 50.98 万局；规则式打它 39.2% | 留着，可换回 |
| `20260926-1407/best.pt` | 09-26 22:52 | 144 万局，vs 贪心 95.2%（**打贪心更强、打像人的对手更弱**） | 留着，可换回 |
| `20260926-0940/best.pt` | 09-26 12:57 | 18 万局 · 混对手 | 不 |
| `20260926-0843/best.pt` | 09-26 08:55 | 中途一版 | 不 |
| `20260926-0033/best.pt` | 09-26 04:36 | 20 万局 · **纯自对弈** | 不 |
| `20260925-2115/best.pt` | 09-25 22:03 | 最早的一版 | 不 |

### 两条最容易搞错的

1. **只认文件名 `best.pt`。**
   `runs/rl/20260927-1155/last.pt` 比 1407 还新（09-27 11:56），但**它不会被加载** ——
   那个 glob 只找 `best.pt`。`last.pt` 是「训练跑完时的那一版」，只在同目录里做对照用。
2. **想强制换一份**：设环境变量 `GUANDAN_WEIGHTS=<路径>`（它的优先级高于「挑最新的」），
   或者直接给 `load_net(path)` 传路径。
   **影子日志的 `session` 行记的就是实际加载的那份**（跟面板走的是同一个
   `resolve_weights`），所以事后可以查，不会骗人。

⚠️ **反过来说：往 `runs/rl/` 里写任何新的 `best.pt`，就等于换掉面板用的模型，而屏幕上
不会有任何提示。** 这就是「两臂训练必须落在不同的 `--out-dir`」这条纪律的由来。

### 这条链是怎么走到的

```
net/launcher.py::main()          一键启停（装证书 → 起抓包 → 开面板 → 退出还原）
   └── net/shadow.py::open_shadow()        影子记录器
         ├── advise.resolve_weights()      ← 上面那个唯一口径
         └── advise.load_net()             QNet + 权重（放 CPU）
   └── net/table.py::run_live(...)         图形面板（tkinter）
```

**注意 `net/panel.py`（终端版面板）与 `net/table.py`（图形面板）是两条并列的入口**，
`launcher` 默认走 `table`，加 `--console` 才走 `panel`。两个都靠 `shadow` 那条链拿模型。

## 二、跑起来的三条命令

```powershell
# 1) 打牌时（面板 + 影子模式）
.venv/Scripts/python.exe -m net.launcher

# 2) 训练
$env:GUANDAN_DEVICE="cpu"      # 实测 CPU 反而更快
.venv/Scripts/python.exe -m train.selfplay 32400 --workers 2 --opp-mix 0.5

# 3) 验收（四层）+ 全量测试
.venv/Scripts/python.exe -m tools.accept_meld      # ① 牌型引擎
.venv/Scripts/python.exe -m tools.accept_sim       # ② 牌局引擎
.venv/Scripts/python.exe -m tools.accept_tribute   # ③ 进贡/还贡
.venv/Scripts/python.exe -m tools.accept_shadow    # ④ 影子模式（整条推理链）
.venv/Scripts/python.exe -m pytest tests/ -q
```

## 四、逐文件

### `net/` —— 主链路（16 个文件）

读网络报文 → 牌局状态 → 面板 → 出牌建议。**这条线的入口是 `launcher.py`。**

| 文件 | 作用 |
|---|---|
| `launcher.py` | **一键启停**：装证书 → 起抓包（带看门狗）→ 开面板 → 退出时**全部还原**。任何一条路径都不许留下断网 |
| `addon.py` | mitmproxy 插件：把掼蛋事件实时写成一行行 JSON → `net/events.jsonl` |
| `rawdump.py` | mitmproxy 插件：把 wss 的**原始帧全量**转储（默认关，靠环境变量开）。⚠️ **它没有被任何代码 import**（mitmproxy 用 `-s` 按路径加载），所以任何「谁引用谁」的检查都看不出它还在用 |
| `protocol.py` | wss 协议解码 —— **只解「服务器 → 客户端」**这个方向 |
| `cards.py` | 牌 ID ↔ 牌面互相转换 + 掼蛋大小排序 |
| `state.py` | **牌局状态机**：把事件拼成一副看得懂的牌局（手牌/出牌/轮次/座位/接风/一局清场）+ 动作流水 `steps` |
| `levelwatch.py` | 从**游戏日志**里读级别（打几）—— 网络报文里没有这个 |
| `advise.py` | **出牌建议的推理链**：`GameState → Observation → 候选 → 打分 → 建议`。⚠️ 它还管**「加载哪份权重」的唯一口径**（`resolve_weights`） |
| `shadow.py` | **影子模式**：每个决策点算一次建议、落盘，局末回填我实际出了什么 → `net/shadow.jsonl` |
| `table.py` | **图形面板**（tkinter）：牌桌 + 右侧「模型建议」栏（用牌面图片画，不写数字） |
| `panel.py` | 终端版面板；`--replay` 可以离线回放抓包 |
| `__init__.py` | 包说明（掼蛋牌局数据的网络读取） |
| `sim/meld.py` | **牌型真源**：合法着法枚举与大小比较（含逢人配、同花顺） |
| `sim/rules.py` | **一手牌的规则引擎**：发牌 / 进贡还贡 / 出牌（含接风）/ 结算名次 |
| `sim/env.py` | **自对弈环境**：700 维状态（按出牌人相对化）/ 143 个动作 / 15×147 历史 |
| `sim/__init__.py` | 包标记 |

### `train/` —— 自对弈 RL（8 个文件）

| 文件 | 作用 |
|---|---|
| `selfplay.py` | **训练主循环**（DouZero 式 DMC）：32 局同步推进 → replay buffer → 一步 MSE → 每万局评测存 best。也管多进程编排与所有命令行开关 |
| `net.py` | `QNet`（LSTM128 + 6×512 MLP）+ 批量打分工具：`q_values` / `q_argmax_batch` / `q_max_batch`（自举用）/ `check_q_scale`（发散守门） |
| `worker.py` | 多进程里的**打牌进程**（纯推理、只用 CPU），跨进程只回传紧凑记录 |
| `replay.py` | **紧凑记录 + 采样时重放**；`mc_targets` 是**标签的唯一产地**，`blend` 是**自举进标签的唯一一处** |
| `pool.py` | 对手池（league + PFSP）。**已证否**（每局不比对照好、每小时少跑 39%），`--pfsp` 默认关 |
| `policies.py` | 策略接口：我们的网络 / 贪心 / 随机 |
| `rule_policy.py` | **规则式「像人」对手**（不压队友 / 留炸 / 按剩牌数卡对手）。移植自开源规则式掼蛋 AI + 用户补的「一手走完风险」+「不许拆自己的炸」两条。vs 贪心 **84.2%** |
| `eval.py` | 评测：`match`（胜率）、`bomb_waste`（炸弹浪费率）、`bomb_rate`（用炸率） |
| `__init__.py` | 包标记 |

### `tools/` —— 验收与运维（11 个文件）

| 文件 | 作用 |
|---|---|
| `accept_meld.py` | **第一层验收**：拿真实对局验证牌型引擎 |
| `accept_sim.py` | **第二层验收**：拿 55 局真实对局回放整局，验模拟器的轮转/接风/终局/记账 |
