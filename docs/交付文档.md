# 掼蛋出牌建议 —— 交付文档

> 2026-09-30 写。**这份只讲「怎么装 / 怎么启动 / 怎么训练 / 怎么量」。**
> 现状与设计见 `docs/superpowers/specs/2026-09-27-current-scheme.md`（**接手先读它**）；
> 每个文件干什么见 `docs/文件地图.md`。

主链路一句话：**读游戏的网络报文 → 还原牌局 → 面板显示 + 模型给出牌建议。**
不碰游戏进程、不模拟点击、**不替你出牌**（只建议）。

## 0. 三条最常用的命令

```powershell
# ① 打牌时：起抓包 + 开面板（退出时全部还原）
.venv/Scripts/python.exe -m net.launcher

# ② 训练
$env:GUANDAN_DEVICE="cpu"
.venv/Scripts/python.exe -u -m train.selfplay 32400 --opp-kind rule --opp-mix 0.5 --workers 2 --out-dir runs/ab/R11_rule *> runs/ab/R11_rule.log

# ③ 量水平（多臂配对，主尺子 = vs 规则式）
.venv/Scripts/python.exe -m tools.ruler runs/ab/R11_rule/best.pt --base runs/rl/20260930-r10/best.pt
```

## 2. 打牌时：`net.launcher`

```powershell
.venv/Scripts/python.exe -m net.launcher
```

一条命令做完四件事，**任何一条失败路径都不许留下断网**：

1. 装 mitmproxy 证书到当前用户证书库
2. 起抓包（**带看门狗**：mitmproxy 一死立刻还原系统代理）
3. 等系统代理真的能连通，再开面板
4. 退出时全部还原（代理 / 证书 / 端口）

| 参数 | 用途 |
|---|---|
| `--dry-run` | 只检查环境，不动系统代理 |
| `--no-panel` | 只起抓包，不开面板（调链路用） |
| `--no-advice` | 关掉影子模式（不加载权重） |
| `--no-show-advice` | 算建议但不显示（记录里如实写 `advice_shown:false`） |
| `--level N` | 手输级别（日志读不到时兜底） |
| `--console` | 用终端版面板（不开 tkinter 窗口） |
| `--selftest N` | **走 N 局把流程走顺再退出**，验证还原路径一条不剩（演示前排练用） |
| `--yes` | 跳过确认 |

**启动时会自己报加载了哪份权重** —— 这一行是判断「换没换源」的唯一依据：

```
影子模式就绪 —— 模型：rl/20260930-r10/best.pt（200,000 局）
```

面板挑权重是「按修改时间挑最新的 `runs/rl/*/best.pt`」，**全仓库只有一处口径**
（`net/advise.py::resolve_weights`）。想强制换一份：设环境变量 `GUANDAN_WEIGHTS=<路径>`。

## 3. 训练：`train.selfplay`

```powershell
$env:GUANDAN_DEVICE="cpu"
.venv/Scripts/python.exe -u -m train.selfplay 32400 `
  --init runs/rl/20260930-r10/best.pt `
  --opp-kind rule --opp-mix 0.5 --workers 2 `
  --out-dir runs/ab/R11_rule *> runs/ab/R11_rule.log
```

第一个位置参数是**秒数**（32400 = 9 小时）。

⚠️ **`GUANDAN_DEVICE=cpu` 是实测最优，不是将就** —— 这个循环以 Python 为主，
上 GPU 反而只抢显存。实测吞吐 ~47 局/秒（2 worker）。

⚠️ **`*>` 不是笔误**：PowerShell 里 `>` 只收标准输出，`*>` 才把所有流收进日志。
**`-u` 也别省**（不缓冲，日志实时落盘）。

### 3.1 关键参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--init <ckpt>` | 无 | 热启动。**ε 起点会自动压到 0.3**（见下） |
| `--opp-kind {greedy,rule}` | `greedy` | 固定对手用哪种「强」。`rule` = 规则式「像人」对手 |
| `--opp-mix F` | `0.5` | 每局以 F 的概率把**一个队**换成固定对手 |
| `--workers N` | `1` | 多进程自对弈 |
| `--out-dir <dir>` | — | **两臂必须落在不同目录**，否则后跑的覆盖 `best.pt`，而面板会**静默换源** |
| `--eps-games G` | `250000` | ε 退火到 0.1 所需的**局数**。**跑短实验一定调小** |
| `--eps-start F` | 自动 | 显式指定 ε 起点 |
| `--snap-every N` | — | 每 N 局存一个池快照 |
| `--buffer N` | `50000` | replay 容量（局） |
| `--bomb-cost λ` | `0` | 动作计价（已试过：方向对、幅度不够） |
| `--mc-mix β` / `--n-step n` | `1.0` / `3` | n 步自举（**已证否**，β=1 时不起作用） |
| `--pfsp` / `--pool-*` | 关 | 对手池（**已证否**） |
| `--learn-all-seats` | 关 | 对照臂专用 |

### 3.2 三条一定会踩的训练纪律

1. **绝不并发两条臂** —— 每条约 4.8 GB，这台机器只够一条（并发过、打爆过）。
2. **热启动的 ε 从 0.3 起退火，25 万局才退到 0.1。**
   所以**续训短于 ~50 万局基本白跑** —— 大半预算花在探索上。
   实测：54 万局的续训只值 +0.7pp（测不出来），78 万局才值 +3.8pp。
3. **`Ctrl-C` 是安全的**（走收尾逻辑），直接关窗口也安全（快照已落盘）。
   快照每 2 万局一份 ⇒ **最多丢 2 万局**。恢复只要换 `--init` 指到最新快照。
   ⚠️ 但**恢复会重启局数计数器**（`--init` 只装权重）。

## 4. 量水平：四把尺子

`vs 贪心` **早就饱和了**（90%+），量不出代差。**主尺子换成 `vs 规则式`。**

| 工具 | 答什么问题 | 典型耗时 |
|---|---|---|
| **`tools.ruler`** | **多臂 × 多种子配对，比谁强**（主尺子） | 4 臂 × 6 种子 ≈ 5 分钟 |
| `tools.ab_compare` | 单臂体检：vs 贪心 / vs 规则式 / 白炸 / 用炸率 | ~2 分钟 |
| `tools.rule_bench` | **规则式自己**的强度 + 三条行为护栏 | ~1 分钟 |
| `tools.opp_headroom` | 「换更强的对手 / 模仿学习」还剩多少可换（反事实探针） | ~12 分钟 |
| `tools.action_margin` | 动作边际 `top1−top2`（候选之间）。⚠️ **要显式给权重路径** | 快 |

```powershell
# 主尺子：现役 vs 候选，同种子配对（方差远低于两次独立测量之差）
.venv/Scripts/python.exe -m tools.ruler `
  runs/rl/20260930-r10/best.pt runs/ab/R11_rule/best.pt `
  --seeds 1002,1003,1004,1005,1006,1007 `
  --base runs/rl/20260930-r10/best.pt
```

**测量纪律（这两条不遵守，读数会骗人）：**

- **单种子 400 局的 sd 约 2.1pp**，比大多数要判的效应还大 ⇒ **至少 3 个种子**。
- **要配对**：同种子 = 同一副牌、同样谁坐哪，差逐局对消。
  两次独立测量之差**不能**当两臂之差用。

## 7. 红线（**这几条别碰**）

| 红线 | 为什么 |
|---|---|
| **`runs/rl/` 绝不能删** | 面板就是从这里挑权重的；删了面板没模型 |
| **不许自动替用户出牌** | 面板只**展示**建议。这是产品红线 |
| **别删 `live/` `synth/` + 根目录散装脚本** | YOLO 兜底线，2026-09-27 决定整条保留。其中 `table_gt.py` 是**逐帧放大核对的人工真值，不可再生** |
| 别在根目录跑训练 | `--out-dir` 必须显式给，否则覆盖别的东西 |

## 8. 已知的坑（都是踩过的）

1. **`best.pt` 的挑选口径是抽签。** 它按训练内 200 局 `vs 贪心` 挑（噪声 ±2pp），
   而一代的真实进步只有 3pp —— **噪声和信号同量级**。
   实测 R8 的 `best.pt` 比它自己的末尾**差 2.0pp**（够抵一整代）。
   ⇒ 引用 `best.pt` 的数要留这个心眼；**要挑权重请用 `tools.ruler`**。
2. **Claude Code 的后台回收器**会在系统内存紧张时杀掉长跑任务（R8 就这么死的）。
   在**启动 Claude Code 之前**设 `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1`
   （写在命令前面没用）。
3. **端口 8080 / 系统代理 / 证书残留** —— 演示前照 `docs/演示清单.md` 过一遍。
4. **日志最坏滞后 20 秒**（够记牌，不够做毫秒级提示）。
5. **级别有两个来源**：网络报文（快）+ 游戏日志（兜底）。日志那条更准，网络那条更快。
