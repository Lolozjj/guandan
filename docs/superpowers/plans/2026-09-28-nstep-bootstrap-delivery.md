### Critical（已修，带回归测试）

**C1 自举项的「视角」接反了 —— 默认 n=3 时约 89% 的自举值符号是错的。**

`Q(s,a)` 学的是「**出手人那一队**」的收益（`encode_state` 一切以出手人为原点、
标签是 `rules.reward(ranks, seat)`），而 `V(s_{t+n}) = max_a Q(s_{t+n}, a)`
取的是 **`s_{t+n}` 处出手人**的视角。出手顺序是 `0→3→2→1`（`rules.NEXT`），
**奇数 n 的那个位置在对家**。后果是 `(1−β)V + βR` 两项互相抵消、标签被往 0 拉 ——
正是 spec §3.1 专门要避免的「塌成常数」，而且**没有任何测试、断言或 loss 异常能看见**
（loss 从 ~3.0 掉到 ~0.9，看着像学好了）。

**我自己独立复现了一遍**（12 局，`greedy_policy`，1407）：n=1/3 时
`corr(V, 标签) = −0.353 / −0.145`，n=2/4 是 `+0.271 / +0.273`；
自举源与标签同队的比例 5.4% / 16.0% vs 89.2% / 88.3%。**方向与量级都对得上评审。**

修法（`train/replay.py::_boot_source_ok`）：自举源必须**与标签同队**、
且**属于学习座位**（后者是老纪律：固定对手的状态不是我们的值），
否则该点**整项退回 MC**。**不取负** —— 取负等于把「对家按最大打」的价值当成我们的，
而行为策略并不是最大，那是另一种偏差，本轮不引入。
`N_STEP` 默认 **3 → 2**（必须偶数；奇数等于没自举）。
日志头对奇数 n 会打一个 ⚠️。

**时序是万幸**：A/B 还没跑，所以这个缺陷**没有代价** —— 否则处理臂测的是坏机制，
然后按预登记的「杀停」把路线②判死，而这条路从没被真正测过。

### 9.3 机制：它是**朝反方向**起作用的（这才是这一轮真正的收获）

判据 2 不是"没变宽"，是**显著变窄**（28%，5.6 sd）。一个自洽的解释：

- MC 标签虽然"不依赖动作"，但它的**噪声很大** ⇒ 不同动作之间的标签**离散度也大**
- 自举把目标换成 `(1−β)·V̄(s′) + β·R`，而 `V̄` 是**状态的平滑函数** ⇒
  两个动作只要把局面带到**相近的后继状态**，目标就相近 ⇒ **跨动作的目标方差被压小**
- 于是 Q 对动作的区分度**变窄** —— 正好是我们观察到的 0.102 → 0.073

⇒ **「一局共享一个标签」这个诊断没错，但自举不是解药**：它把"标签不依赖动作"这件事
**变得更严重**（不是更轻）。这条结论是可复现的、机制层面的，不是"效果不显著"。

### 9.4 所以按预登记，下一步是**质疑「值函数 + argmax」这个框架**

不是再换个目标（路线②已经是"换目标"了）。可选方向（含调研来源）：

| **模仿学习**（跟一个强策略学） | `LSTM-Kirigaya/NUAA-guandan` 用的就是模仿+RL | 中：需要强 teacher |

## 11. 候选排序（listwise）的设计推演：**在现有数据上不成立**（2026-09-28）

用户选了「上候选排序」，但推演发现它要么退化、要么成本不可承受。**结论先记在这里，
免得下一个会话再试一遍。**

### 11.1 排序需要一个「per-候选」的信号，而最自然的两种写法都退化

把同一个局面下的候选记为 `a_1..a_k`。**同一局面下所有候选共享同一个终局标签 `R`**
（这就是 §1 那个诊断）。两种自然写法：

- **回归式**（每个候选都回归到自己的值）：目标全是 `R` ⇒ **所有候选同一个目标** ⇒
  任何 listwise loss 的最小值都是「给所有候选同一个分」⇒ **学不到排序** ✗
- **分类式**（把「实际出的那一手」当正样本、其余当负样本）：那是在**模仿自己的行为策略**。
  而行为策略就是 ε-greedy 的自己（ε=0.1）⇒ ≈ 模仿自己的 argmax ⇒ **不动点**，
  不产生任何新信息 ✗

### 11.2 最便宜的「per-候选信号」正好是路线②已经实测过的那一个

要每个候选各自的分数，最省的做法是 `score(a) = V̄(s′_a)`（打完 a 之后局面的值）——
**那就是路线②在 `n=1/2` 时做的事**（`y = (1−β)·V̄(s_{t+n}) + β·R`）。而实测：
它让 **动作边际变窄 28%（≈5.6 sd）** ✗。
机制也一致：`V̄` 是**平滑函数** ⇒ 不同候选带你去的后继局面**彼此相近** ⇒
分数彼此相近 ⇒ 边际只会更薄，而且**只能和当前值函数一样准**（自我参照）✗

### 11.3 要成立就得上 rollout/搜索，成本是另一个量级

真正不依赖当前值函数的 per-候选信号只有**对局级 rollout**（每个候选各打到底）
或**浅搜索**。成本：每个决策点 K 次 rollout × 一局约 130 步 ⇒
训练成本抬到 **K×130 倍**量级，而我们的环境是**纯 Python 枚举**（本来就比 C++ 的实现慢一截）
⇒ **在这台机器上不可承受**。

### 11.4 同一个位置上有可行的替代：**策略式（REINFORCE / PPO）**

关键区别：**回归**把同一个 `R` 喂给所有候选（所以「标签不区分动作」是致命的）；
而**策略梯度**只作用在**实际出的那一手**上（`∇log π(a|s)·R`）——
**用的是同一个现成的标签，却天然是 action-dependent** ✓ 不需要任何新信号源 ✓
