## 四、实测与两条 spec 更正（都已写进 §14）

### ① §5.3 的 replay buffer「最近 50 万局」**按字面做不到**

它只说了存多少局，没说**存什么**：

```
存编码好的张量：每局 1.53 MB -> 50 万局 = 747 GB      （做不到）
存紧凑记录 + 采样时重放：每局 1.9 KB -> 50 万局 = 923 MB（做得到，重放约 27 ms/局）
```

默认取 5 万局（92 MB），`--buffer 500000` 可开到 spec 的原数。

### ② §5.3 的「batch 32 局」不能从斗地主直接搬

斗地主一局约 20 个决策点 -> 32 局 ≈ 640 个位置。**掼蛋一局实测 131.6 个决策点**
-> 同样 32 局是 **约 4,200 个位置，6.5 倍**。要按位置数定 batch。

### ③ 训练步的瓶颈是**网络前向**，不是规则引擎

规则引擎已优化到 95 局/秒，但接上训练循环只有 7 局/秒。剖面：

```
q_values 37,689 次调用，累计 70.8 秒   <- 一次前向只算一个局面（候选 <10 个）
```

改成 **32 局同步推进**（各走一步、攒成一批再前向）-> **7 → 14 局/秒**；
评测器同样的改法 -> **200 局 30.2s → 7.1s**。

### ④ 评测噪声（判据阈值的依据）

同一网络换 6 个种子各测 200 局 -> **4.8% ± 1.4%**（二项理论 ≈1.5%）。
所以 200 局够用、**100 局不够**（±5%）—— 早期用 100 局测出过「29% vs 15%」，
看着像 bug，其实只是样本太小。

### ⑤ 贪心基线的强度（判据有没有意义取决于它）

```
随机 vs 随机 = 50.0%     <- 评测无偏、赛制对称
贪心 vs 随机 = 83.2%     <- 基线明显强于随机 =>「打得过贪心」是有意义的门槛
贪心 vs 贪心 = 49.3%     <- 对称性自检
```

## 五、下一个会话：影子模式（spec §8.2 / §8.3）

**用户要的是「先投入使用，我看看效果」。** 影子模式第一版的定义（spec §8.2）：

> **不给建议，只记录**。每个决策点把模型建议写进日志，同时记下**实际出了什么**、
> 那一局最后赢没赢。攒几十局后回看：建议与实际选择的**分歧点**，以及那些分歧局谁赢。

**为什么必须先做这个**：模型在模拟器里的胜率只证明它在**我们的规则**下强。
影子模式是**唯一能在真实游戏上核对**的方式，而且零风险（不动游戏、不出牌、只写日志）。

### 要做的东西

1. **`net/advise.py`**（spec §8.1 的推理链）：`GameState` -> `meld.legal_moves` -> 打分 -> 建议。
   **推理不加载模拟器**，只需要裁判 + 权重文件。
2. **`net/shadow.jsonl`**：一行一个决策点，风格与 `net/events.jsonl` 一致
   （追加写、面板可跟读、`net/replay.py` 那套离线复盘能用）。
3. **接进现有网络面板**（`net/table.py` / `net/panel.py`）：轮到我时算一次建议并落盘。

### ⚠️ 四个会咬人的点（写在这里免得重推）

1. **状态编码必须与训练时一致。** 网络吃的是 `Observation`（`net/sim/env.py`），
   其中**座位是相对化的**：索引 0 = 自己。所以advisor 要用 `seat = 我` 构造 Observation，
   而不是把绝对座位号塞进去。`encode_state` 只吃 `Observation`（这是刻意设计的）。
2. **历史（最近 15 手）面板里没有现成的。** `encode_history` 要的是 `Hand.steps`
   那种「谁出了什么」的序列 —— 面板的状态机（`net/state.py`）得**自己维护一份
   ≤15 步的动作流水**，并在每个决策点按当时的状态取（**不能用打完之后的**，
   那会把后面才发生的牌塞进历史，是「未来信息」泄漏）。
3. **级别**（打几）必须对。级别错 -> 逢人配全错 -> 建议全错。面板从 msgid 3008 拿到它
   （见 HANDOFF「二之二」），要确认推理链真的用上了。
4. **红线：绝不替用户出牌、不往游戏发任何报文。** 模型只输出给人看的建议（spec §8.4）。

### 两笔要记在前的账

- **进贡在训练里是关着的**（`EnvConfig.tribute=False`）—— 因为那条规则本身还是基线
  （贡最大的牌 18/25，见 spec §13.8）。影子模式**不受影响**（它不模拟，只读实时状态）。
- **级别是均匀采样的**（spec §13.1 的代价）—— 真人是从打 2 一路爬上去的。
  影子模式正好能**顺带量出**这个偏差有多大：真实对局的级别分布 vs 训练时的均匀分布。

### 影子模式之后（spec §7 剩下的、以及 §8.3）

- **vs 人类着法**（spec §7 第三行，仅参考）：拿 55 局真实记录量一次，很便宜。
- **反馈回收**（spec §8.3）：用户不采纳建议时回收这个信号。
  **注意**：不采纳**不等于**模型错，所以这份数据用于**分析**，**不直接当训练标签**。
- 曲线已趋平 -> 想再涨要动**网络结构或状态特征**，不是加时长。
