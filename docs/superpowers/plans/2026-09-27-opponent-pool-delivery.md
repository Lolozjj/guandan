# 对手池交付台账（2026-09-27）

> 计划：`docs/superpowers/plans/2026-09-27-opponent-pool.md`
> 规格：`docs/superpowers/specs/2026-09-27-opponent-pool-design.md`

**一句话结论**：**代码做完了、测过了、能跑；而那一轮实验作废** ——
池子在混合局里只拿到 **20%** 的份额（设计是 80%），**整轮只给了设计剂量的 1/4**
（评审抓到的，见 §3.1），而且实验被内存打死在 2.1 万局。
所以「池子有没有用」这个问题**这一轮没有回答**。
真正的收获是另外三件：**两件意外发现**（§3.4 / §3.5）与**一次评审救回来的错误结论**（§9）。

> ⚠️ 这份台账在评审后**改过结论**。改动前它写着「池子没兑现、杀停条件触发」——
> 那个说法建立在一个剂量错了的实验上，是**错的**。§3.1 与 §9 记了全过程。

## 1. 怎么跑

```powershell
$env:GUANDAN_DEVICE="cpu"
# 开池子
.venv/Scripts/python.exe -m train.selfplay 32400 --workers 2 --opp-mix 0.5 --pfsp
# 不开（老行为，A/B 的对照臂）
.venv/Scripts/python.exe -m train.selfplay 32400 --workers 2 --opp-mix 0.5
```

新增开关：`--pfsp`（开池子）/ `--init <ckpt>`（热启动）/ `--out-dir` /
`--learn-all-seats`（**对照臂专用**：恢复「固定对手的着法也进训练目标」的老行为）/
`--snap-every N` / `--pool-size N`。

## 2. A/B/C 三臂

**三臂同种子、同预算（3600 秒）、同 `--eps-games 60000`、同 `--init 1407`**，
只差「有没有修 `expand`」与「有没有池子」：

- **A_old** = 老行为（`--learn-all-seats`，纯贪心对手）
- **C_fix** = 只修 `expand`（默认，无 `--pfsp`）
- **B_pool** = 修 `expand` + 池子（`--pfsp`）

同尺子 = 同一批 400 局（`match(..., seed=1002)`）+ 同一组对手（1407 / 0033）。

| 存档 | 局数 | vs 贪心 | 炸弹浪费·自对弈 | **炸弹浪费·对池中位** |
|---|---|---|---|---|
| **起点** `1407/best.pt` | 1,441,760 | **95.2%** | 6.4% | **4.2%** |
| A_old @20k | 20,000 | 90.2% | 5.8% | 4.6% |
| C_fix @20k | 20,000 | 92.8% | 5.0% | 4.2% |
| B_pool @20k | 20,000 | 94.5% | 5.6% | **5.4%** |
| B_pool @108k | 108,672 | 91.5% | 6.0% | 4.2% |

B_pool 是唯一跑完的（108,672 局 / 3621 秒 = **30 局/秒**）；A、C 在 ~2.1 万局被内存打死。

## 3. 结论

### 3.1 ⚠️ **这轮实验作废：池子只拿到设计的 1/4 剂量**（评审抓到的）

**先看这条，它把下面所有数字的解释都改了。**

`pick_opponent` 的贪心份额在生产路径上传的是 `train_parallel` 里那个**老二分的**
`greedy_share=0.8`，而不是池子的 `pool.GREEDY_SHARE = 0.2`
（后者只当了函数默认值，**从没被生产调用到**，也没有 CLI 开关调它）。
后果：

| | 设计 | 实际 |
|---|---|---|
| 混合局里池成员占 | 80% | **20%** |
| 全局局里打池成员 | 40% | **10%** |

B 臂日志第一行自己就写着「对手混合 50%（其中贪心 **80%**）」——
**现场证据一直在，我读着它写下了结论却没想到去看池子那一路**。
`train/pool.py` 里还留着一句「取 0.8」的过期注释直接压在 `GREEDY_SHARE = 0.2` 上面，
两套口径并存正是本仓库最忌讳的「副本会漂」，这次漂掉的是整轮实验。

**所以下面这组数字测的不是「设计的池子」，而是「剂量 1/4 的池子」。**

### 3.2 那一轮的可比数字（同局数 2 万局）

| 存档 | 局数 | vs 贪心 | 炸弹浪费·自对弈 | 炸弹浪费·对池中位 |
|---|---|---|---|---|
| **起点** `1407/best.pt` | 1,441,760 | **95.2%** | 6.4% | **4.2%** |
| A_old @20k（老行为） | 20,000 | 90.2% | 5.8% | 4.6% |
| C_fix @20k（只修 expand） | 20,000 | 92.8% | 5.0% | 4.2% |
| B_pool @20k（修 + 1/4 剂量池子） | 20,000 | 94.5% | 5.6% | 5.4% |
| B_pool @108k | 108,672 | 91.5% | 6.0% | 4.2% |

看出来的只有：**池子臂的炸弹浪费不比对照臂低**（同局数 5.4% vs 4.2%，方向是反的），
B 跑到 10.8 万局才回到起点的水平，而且**没有任何一臂在 `vs 贪心` 上超过起点**。

**但不能就此给池子判死刑**，两条理由：

1. **剂量错了**（§3.1）—— 测的不是设计的东西。
2. **实验被内存打断**（§4.1）—— 只比到 2 万局，而 1407 当初练到 **18 万局**才到顶。

准确说法：**没测出来**。

### 3.3 杀停条件：不适用

spec §1.5 的杀停（「池子臂的炸弹浪费不比对照臂低 1 个标准差就停」）
**建立在一个按设计给药的实验上**；这一轮剂量错了，所以它**不构成**杀停的依据。
要判进退，得先按 §9 的修复重跑。

### 3.4 意外发现一：`--init` 与 ε=1.0 是**坏组合**（比池子更值得先修）

三臂**全都**比起点差（95.2% → 90~94.5%），这是共同的、比池子更大的效应。
原因指向：**热启动之后 ε 仍然从 1.0 开始** —— 头一万多局在做近乎随机的探索，
把缓冲区和权重一起冲淡。`--init` 应该同时把 ε 压到一个低的起点
（或至少暴露一个 `--eps-start`）。B 的曲线也支持这个：它到 **30k 局**才短暂超过起点
（98%），之后又掉下去。

### 3.5 意外发现二：固定 200 局评测**有系统性偏差**

C_fix 的 `snap_20000`：日志里那次 200 局评测报 **96.5%**，
而同一份权重在**同种子的 400 局**上只有 **92.8%** —— 也就是第 201~400 局只有 89.1%。
两次数的是同一批牌的前 200 局。

→ `>> 评测 @ …` 那些行**不能当成泛化能力**，它只是一批固定牌上的成绩（这一点
`current-scheme.md` §六 已经写过「不能当唯一依据」，但偏差有 3.7 个百分点，
比我原先说的严重）。**判据（退出码）本身仍然有效**（跟历史跑可比），只是别过度解读。

## 4. 我这边的失误（都记下来）

### 4.1 三臂并发 → 内存打死（本次实验作废的直接原因）

我裁定三臂并发跑，理由是「20 核吃得下」—— 只算了 CPU，**没算内存**。
三臂 ×（learner + 2 worker），每个 worker 实测 RSS ~1.2 GB，撞上机器的提交上限。
A、C 各在 ~2.1 万局死于 `numpy ArrayMemoryError`，worker 挂掉，
训练按纪律**响亮地炸出来**（`RuntimeError: worker [1] 挂了（exitcode=[1]）`）——
**这一次「失败必须响」是对的**，没有静默降速。

### 4.2 计划里被实测推翻/补上的四处

1. **`--learn-all-seats` 没穿过 worker** —— 不补的话对照臂用 `--workers 2` 时开关完全无效。
2. **预热成员的权重算错了两次** —— 先给了个量纲不同的常数 `1.0`（`p(1−p)` 最大只有
   0.25，等于让它比健康成员重 4 倍），改成「把 p 当 0.5」之后**还是错的**：
   0.5 是 `p(1−p)` 的**最大**值，于是刚加进来的 0 局成员最重 —— 实测它吃掉了
   **38.4%** 的采样权重。最终落到「拿均匀那一份 `1/K`」。两次都是测试/实测抓出来的。
3. **池子被无条件接上** —— 规格写的是「一臂 `--pfsp`、一臂纯贪心」，
   但实现里没开关，两臂就差了两件事。补 `--pfsp`（默认关）。
   顺带修掉 `if "--pfsp":` **恒真**的写法（漏了 `in argv`）。
4. **规格 §3.2「胜者不用加」被推翻** —— 实测 `expand` **18.3 ms/局**，
   而学习进程每秒要处理几十局池对局。改成 `GameRecord.won`（一个 bool）。

### 4.3 计划的两臂 → 执行时的三臂

原计划 A（老行为）vs B（修 + 池子）差了两件事，赢了也不知道是谁的功劳。
加 C 之后 B−C 是池子净效果、C−A 是 `expand` 修复的效果。这个改动是对的
（它确实分出了「C 比 A 好」），代价是内存翻倍 —— 见 §4.1。

## 6. 已知风险

| 风险 | 现状 |
|---|---|
| **不可复现** | 池子采样依赖在线胜率 ⇒ 只保证「同种子 + 同池子状态」可复现。**别承诺更多** |
| **内存** | 池子 = 每个成员 7.8 MB × 池子大小 × worker 数。三个池子臂并发就把机器打爆过（§4.1） |
| 池子塌陷 | `pool_report` 返回「是否塌陷」，日志里每个成员一行；有效成员数低于 2 报警 |
| 吞吐 | 单臂 30 局/秒（三臂并发时），与不开池子的对照臂**同量级** |

## 7. 没做完的

1. **A/C 两臂没跑完**（内存打死在 2.1 万局）⇒ 只比到 2 万局。要下结论得重跑。
2. **重跑的前提是修 §3.4**：`--init` 要同时压 ε，否则热启动会被头一万局的随机探索冲掉，
   任何「从 1407 出发」的实验都会被这个效应盖住。
3. 只跑了 1 小时；1407 当初练到 18 万局才到顶，池子真正的效果点可能在更远处。
4. 池子对 `bomb_waste` 的作用**没测出方向**（见 §3.2）。
5. **按设计剂量（池份额 80%）的那一轮还没跑过** —— 这是 §8 的第 1 条。

## 9. 评审与修复轮（2026-09-27，全分支评审之后）

一个**新上下文**的评审者（最强模型）看了 `6f57380..650a96f` 的整段分支。
它抓到 **1 个 Critical + 3 个 Important + 9 个 Minor**，其中 Critical 直接推翻了
本台账原先的结论。

### 9.1 Critical：池子只拿到设计的 1/4 剂量 → 那一轮实验作废

见 §3.1。评审是**自己把生产链路跑通**复现出来的（`worker_cfg` → `pick_opponent`：
79.7% 贪心 / 20.3% 池成员）。

### 9.2 Important（都已修，每条先有会失败的测试）

| | 问题 | 修法 |
|---|---|---|
| I1 | 种子池为空时 `--pfsp` **静默**退化成纯贪心臂，唯一那句话还把「空」误报成「塌陷」 | 提取 `load_seed_pool`；空池**直接炸**（`RuntimeError`，提示先跑一次不带 `--pfsp` 的） |
| I2 | 池子塌陷只写进 `r["pool_collapsed"]`，没人看 —— 退出码照样 0、照样印「判据过了」 | `main()` 把塌陷算成失败：打印告警 + **退出码 1** |
| I3 | `--pool-size` 只管运行时新增的成员，种子那 5 个不受约束 | `load_seed_pool(paths, pool_size)` **按 pool_size 截断** |

### 9.3 被评审证据升格进修复轮的一条 Minor（M3）

评审实测：一个刚加进来的 **0 局成员吃掉了 38.4% 的采样权重**（`runs/ab/B_pool.log`）。
我的「把预热成员的 p 当 0.5」落在 `p(1−p)` 的**最大**值上，等于「越没测过越优先」——
正是规格 §3.2 自己警告的那个失效模式，只是被压小了 4 倍而没消除。
改成**拿均匀那一份 `1/K`**（规格 §5.3 与测试名原本就是这么写的）。
代价：这一条我修了三次才对（常数 1.0 → p=0.5 → 均匀份额）。

### 9.4 其余 Minor：**不修，记在这里**（按流程 Minor 不进修复轮）

- **M1** worker 可能在被挤掉的成员上多打 ≤1000 局（等到下一次 `weights` 广播才删），
  期间 learner 会给一个已不在池里的 mid 记胜率（后来算权重时被静默丢弃）。有界、今天无害。
- **M2** `pool.load_members` **没有生产调用方** —— 种子只从 `best.pt` 取，
  磁盘上的 `pool/snap_*.pt` 从不回读。于是每次重跑池子都从同样的 5 个种子起步，
  而 spec §3.1 里「快照是为了让池子有原料」这半句只兑现了一半。**下次重跑前该接上。**
- **M4** `pool_sds[mid]` **不是冻结的快照**：`.cpu()` 在 CPU 张量上不拷贝，
  它与活网络的参数共享存储（只有队列的 pickle 让它真冻住，而 pickle 与 feeder 线程有竞态）。
  今天的影响约一个 Adam step，但任何未来消费者（比如接上 M2）会**静默**拿到当前模型。
- **M5** `--pfsp` 只有 `train_parallel` 认，`--workers 1` 会 `TypeError` 崩。
- **M6** `--pfsp --learn-all-seats` 一起给会静默产出垃圾（`learn` 变成四家 →
  `plan_step` 永不派发到成员 → PFSP 表填的是成员没打过的局的胜率）。
- **M7** `train_parallel` 的池子记账（`next_mid` / FIFO 剪枝 / 快照触发广播）**没有测试**；
  「无开关时 rng 流与老行为一致」也没人钉。
- **M8** 台账表的来源脚本 `ab_compare.py` 在 `.gitignore` 里（`.superpowers/`），
  清理后数字不可复现。
- **M9** HANDOFF 与现用方案推荐的训练命令**没带 `--out-dir`** —— 照它跑，
  新 run 的 `best.pt` 会在几分钟内被面板当作最新权重挑走（静默换源）。

## 10. 下一步（评审后的顺序）

1. **修 `--init` 的 ε**（一行：热启动时把 ε 起点压低）。最便宜、最确定的一刀，
   而且**不修它，任何热启动实验都白做**。
2. **按设计剂量重跑**（`--pool-greedy-share 0.8`，即池份额 80%），
   **两臂或串行**（内存），预算 2~3 小时 —— 让局数越过 1407 的 18 万局峰值区。
   顺手把 M2（回读快照）接上。
3. 若池子仍无效果 —— 按 spec §1.5 转「换目标（信用分配）」，**不是加算力**。
