### 训练速度与两个对照（`train/smoke.py`）

```
随机 vs 随机（两队都随机）            51.1%   <- 评测无偏、赛制对称
「座位 0/2 能过就过」这个确定性坏策略   0.0%   <- 评测认得出坏策略
```

## 五、实测推翻计划/规格的地方（这些是本次最重要的产出）

1. **出牌轮转：下家是 `(s - 1) % 4`，不是 `(s + 1) % 4`**（顺序 `0 → 3 → 2 → 1`）。
   按直觉写，**55 局真实对局一局都走不通**。见 spec §13.7。
2. **每出一手，`passed` 要清空**（一手打出 = 重新开一轮）。
   不清空的话 55 局里只有 4 局能走通。
3. **「双上 → +3」只对了 13/24 局**，另 11 局实测是 **4**，且同一 `Rank`、同一战前
   级别都能出 3 和 4 ⇒ 依赖本计划没抓的字段（属升级/过A 范畴）。见 spec §13.4。
4. **倍数不是打炸弹抬上去的**：54 局里 `TotalBombRatio` 有 49 局是 1（其中 36 局
   手上有 5~16 个炸弹/同花顺）。真正的倍数是 `FinalDoubleRatio ∈ {1,1.5,2,2.5}`，
   那是**发牌前选的加倍**，一手之内不变 ⇒ **对最优策略零影响**。
   ⇒ reward 默认不带倍数，留 `rules.MULTIPLIER` 一行开关。见 spec §13.4。
5. **「还贡 ≤ 10」是硬证据（25/25）**；**「还贡给哪一张」不是**（25 条里不唯一），
   模拟器定死成「2..10 里最小的」。
6. **`as_meld(cards)` 与 `melds_from(整手牌)` 会对同一套牌给出不同读法。**
   seed=16 那局（打 6）：`melds_from` 给 rank=13 的三带二、`as_meld` 给 rank=1。
   于是「`actions()` 把它当候选列出来、`play()` 却判压不过桌面」。
   `play()` 改成先取整手牌的全部读法、再选压得过的那条。
   **根因在最终评审里挖到底了**：`melds_from` 的三带二让自然牌贪婪占位、
   去重又只留「最先产出的」那条 —— 结果**同一手牌能不能出，取决于一张没出过的牌**。
   已修（见「六之二」）。
7. **进贡规则维持「贡手上最大的牌」，不加豁免**：三条候选规则的实测得分是
   贡全手最大 **18/25**、除大王 13/25、除大王与级牌 5/25；而且**有 8 条确实贡了王**，
   与「王不贡」直接冲突。7 条不符（6 条持王、1 条持级牌）不足以推出稳定规则。见 spec §13.8。

### 我做的判断（计划没覆盖、或计划说「再决定」的）

1. **`_biggest` 不加豁免**（进贡）。计划原话是「对不上就逐条报出来…再决定改不改实现」，
   数据不支持任何简单豁免（见「实测推翻」7）。**而且进贡在训练里默认关**（`EnvConfig.tribute=False`），
   所以这条不确定性**不阻塞 Plan 3**。
2. **`encode_history` 每行多带 4 维相对座位** —— 对 spec §4.2 的**有意偏离**。
   理由：同一样 9♠ 是下家出的还是对家出的，对判断局面完全不同。动作编码本身仍严格按 §4.2。
3. **冒烟不做 replay buffer**（spec §5.3 的 50 万局）：它的采样/淘汰逻辑不该在冒烟里被信任。
4. **`encode_history(hand, seat)` 收明牌 `Hand`**：只读 `hand.steps` / `hand.level`，
   靠一条对照测试 + 反向对照钉住（注入对手手牌 → 转红）。
5. **两条「预期通过」的测试都做了反向对照**（明牌泄漏、历史泄漏）：
   注入泄漏后 41/43 条转红、还原后全绿。**预期通过的测试如果不证明它会失败，就什么都没证明。**

## 八、Plan 3 从哪儿开始

1. **先解决吞吐**：31.9 局/秒 ⇒ 千万局要 3.6 天（还不含网络）。要么换语言/加速，
   要么把规则引擎批量化。**这是 Plan 3 的第一件事，不是最后一件。**
2. 然后才是 DMC 训练循环（replay buffer、规模、评测曲线）。
3. 评测的判据别只看「胜率有涨」：**先跑那两个对照**（随机 vs 随机、能过就过），
   它们把「环境坏了」和「没学会」分开 —— 本次靠它们才没在 12% 胜率上误判成 bug。
