# 换框架：策略式（REINFORCE / 策略梯度）—— 设计

> 2026-09-29。前置阅读：
> `docs/superpowers/plans/2026-09-28-nstep-bootstrap-delivery.md` §9（路线②证否）、
> §11（候选排序为什么不成立）、
> `docs/superpowers/specs/2026-09-27-current-scheme.md` §四（现用训练思路全貌）。

## 1. 目标与成功判据

**要治的病**：模型给的推荐牌还不够好（用户 2026-09-26 报的「有普通牌能压却出炸」是其中一例）。

**已经试过四条路，全没治**（都记在台账里，别重复跑）：混入固定对手 / 对手池（league+PFSP）/
动作计价（炸弹代价）/ **换目标（n 步自举）**。

**这一轮要动的是框架本身**：现在是**值函数 + argmax** ——
学一个标量 `Q(局面, 每一手)`，决策时取最大。

**根因（2026-09-28 收敛，有数据）**：一局约 132 个决策点**共享同一个终局标签 `R`**。
- 路线②试过"让标签去看后继局面"——**方向反了**：自举换成平滑的 `V̄(s')`，
  把**跨动作的目标方差压小**了，动作边际从 0.102 **窄到 0.073（≈5.6 sd）**，
  而 `vs 贪心` 同时掉了 2.2pp（2.0 sd）⇒ 按预登记杀停。
- 候选排序（listwise）**推演后也不成立**：同一局面下所有候选共享 `R` ⇒
  回归式退化成"给所有候选同一个分"；分类式退化成"模仿自己的行为策略"。
  要 per-候选信号就得上 rollout/搜索，成本 K×130 倍，不可承受。见台账 §11。

**为什么策略式能绕开这一条**（这是本方案的全部理由）：
- **回归**把同一个 `R` 喂给**所有**候选 ⇒「标签不区分动作」对它致命。
- **策略梯度**只作用在**实际出的那一手**上：`∇log π(a|s)·(R − b)`。
  **用的是同一个现成的标签，却天然是 action-dependent** —— 不需要任何新信号源。

这也是 SOTA 项目走的路：`Calix-L/DanKS`（金山 AI 产品中心，598★）**第三代就是 PPO**。

### 成功判据（预登记，不许事后改）

⚠️ **主判据换掉了**：`vs 贪心` 已经饱和（现役 93.8%），**没有区分度**。
改用 2026-09-28 新加的**第二把尺子 `vs 规则式`**（规则式对手 = 不压队友 / 留炸 /
算剩牌卡对手；现役 `1407` 对它只有 **88.2%**，多 5.6pp 余量）。

| # | 判据 | 为什么 |
|---|---|---|
| **1** | **`vs 规则式` 比对照臂好 ≥1 sd**（3 个种子均值，同一局数） | **主判据**。换框架必须**证明自己更强**，不是"没退步" |
| 2 | `vs 贪心` 不掉 ≥1 sd | 守门人（防"赢了新尺子、输了老尺子"） |
| 3 | **策略熵不许塌** | 熵塌到 0 = 退回确定性的 argmax = 白换框架。有守门（§6） |
| 4 | `bomb_waste` 两个数不升 + **用炸率不塌** | 沿用老守门人 |
| 5 | 真机影子日志同向 | **要用户打牌**，拿不到就如实写「没有真机证据」 |
| **6** | **杀停**：判据 1 不满足 ⇒ **停「策略式」**。到那时不该再换算法，该换的是**别的东西**（见 §7） | 预登记 |

⚠️ **判据 3 是这一轮特有的**：`vs` 那两条是"结果指标"，而熵是**机制指标** ——
它回答"我们真的在做策略梯度吗，还是它悄悄退化成了 argmax"。
（路线②的机制指标是动作边际；策略式的机制指标就是**熵**。）

## 2. 已确认的事实（都带证据，别重新推导）

- **回归治不了**：见 §1 的根因与两条已证否的路（路线② / 候选排序）。
- **策略梯度用同一个标签却天然 action-dependent**：`∇_θ log π(a|s)` 只对**采样的那个 a** 非零。
- **现役最强 `1407`**（144 万局）：`vs 贪心` 93.8%、**`vs 规则式` 88.2%**（3 种子均值，
  sd ≈ 2.1pp）—— 这是本方案的**起点**。
- **网络可以不动**：现在的输出就是一个标量 `z(s,a)`。把它**当 logits 用**，
  `π(a|s) = softmax_a z(s,a)` ⇒ **结构不变、权重可加载** ⇒
  `--init runs/rl/20260926-1407/best.pt` **照旧能用**，而且
  **初始化出来的策略的 argmax 就是老的 argmax**（两臂从同一个强度起步 ✓）。
- **成本有实测口径**：`log π(a|s)` 要对**全部候选**算 logits ⇒ 前向行数约 **10×**
  （现在是"每个决策点只算选中的那一手"）。这个形态**路线②量过**：
  51.7 → 34.6 局/秒，**−33% 吞吐**。本方案按同一数字做预算。
- **`_tensors` 现在只铺"选中的那一手"**（`train/selfplay.py:430`），PG 要改成铺全部候选。
- **多进程那条路天然有 staleness**：worker 每 1000 局才拿一次新权重
  ⇒ 那部分数据严格说是**旧策略**的（off-policy）。这是 PG 的真实代价，见 §3.4。

## 3. 架构

### 3.1 策略怎么参数化（**不改网络**）

```
π_θ(a | s) = softmax over 合法候选 a of  z_θ(s, a)
```
`z_θ` 就是现在那个标量输出（现在被解释成 `Q`，这里被解释成 **logit**）。
⇒ 网络一行不改、权重格式不变、`--init` 照旧 ✓

两个要点：

- **logits 的尺度**是学出来的。从 DMC 权重热启动时，logits 大概在 ±3 量级
  ⇒ 初始策略**偏尖**；熵项（§3.3）会把它调回来。
- **决策路径不变**：`argmax_a z(s,a)` 就是策略的众数 ⇒ 面板/影子模式/评测器全不用改 ✓
  （`net/advise.py` 走的就是 `q_values` + argmax ✓）

### 3.2 目标函数

```
L = − (1/N) Σ_i  log π_θ(a_i | s_i) · (R_i − b)  −  β_ent · H(π_θ(·|s_i))
```

- `R_i` = 那一局的终局分，**从出牌人视角**（零和，±points）—— **与现在同一个标签** ✓
- `b` = **基线**。初值取**`R` 的滑动均值**（不学 V 网络）。理由：
  现在 95% 的局都赢 ⇒ `R` 的方差本来就小 ⇒ 滑动均值够用，
  而学一个 V 头要多一处能出错的地方。**这是刻意的简化**，不是没想到。
- `β_ent` = 熵系数（初值见 §8）。**熵同时承担探索** —— 见 §3.3。
- `γ = 1`（有限回合、无折扣），与现状一致。

### 3.3 ε 退火 → 熵（**这是行为上最大的变化**）

现在靠 **ε-greedy 探索**（按局数从 1.0 退到 0.1，25 万局）。策略式里
**从 π 采样本身就是探索** ⇒ ε 取什么值都没意义了。

- PG 模式下 **`--eps-*` 全部失效**，改由 `β_ent` 管探索强度
- ⚠️ **日志头必须说清楚这件事**（"ε 不适用；熵系数 β_ent=x"）——
  本仓库纪律：**换源必须可见**。否则日志上写着 `ε 起点 0.30` 而实际没用 ✗
- ⚠️ **不**做熵退火（v1）。ε 退火那一课（按局数退、别按时间）说明探索调度很要紧，
  但那是**另一件事**，同时改两件会分不清是谁的功劳 —— 本仓库吃过这个亏。

### 3.4 数据：**on-policy，不用 replay buffer**

这是 PG 与 DMC 的**定义性差别**：

| | DMC（现在） | 策略式 |
|---|---|---|
| 数据 | 从 5 万局 buffer 里**有放回采 32 局**（可以是旧策略打的） | **只用刚打完的那一批**（严格 on-policy） |
| buffer | 必需（提高样本利用率） | **不用**（用了就是 off-policy，要重要性采样） |

具体做法：**PG 模式下 `buf.add(rec)` 直接不调用**（结构上钉死 on-policy，
顺便省掉那 92 MB），loss 只用这一批 ——
单进程用现场抓的 `caps`；多进程用 learner 侧重放出来的那批（见下面的⚠️）。

⚠️ **多进程的 staleness**：worker 每 `WEIGHT_SYNC_GAMES`（默认 1000）局才拿一次新权重
⇒ 那部分数据是**旧策略**的。处理方式：

- **PG 臂把广播间隔调到 200 局**（`--weight-sync-games 200`）。代价：每次广播
  传 7.8 MB，44 局/秒时约 4.4 次/秒 ≈ **35 MB/s 的本机 IPC** —— 可接受，但要记在案
- 备选（**不采用**）：单进程跑（完全 on-policy）—— 吞吐腰斩（学习进程是瓶颈），
  而且两臂的机器条件就不一样了 ✗
- **已知偏差，写在这里而不是假装没有**：200 局的 staleness 仍然是 off-policy 的近似

### 3.5 谁在学、谁是对手（不变）

- 学习那一队：从 `π` **采样**（不再是 ε-greedy）
- 固定对手那一队：`greedy` / `rule` / `random` / 池成员，一律照旧（argmax 或固定策略）
- **固定对手的决策点不进 loss**（`learn` 过滤器），与现在一致 ✓

## 4. 关键取舍

| 取舍 | 选择 | 为什么 |
|---|---|---|
| 换什么 | **策略式（REINFORCE + 熵）** | 唯一能用**现成标签**、又天然 action-dependent 的做法（§1） |
| 网络结构 | **不动** | 复用现成标量当 logits ⇒ 权重可加载、决策路径不变、面板不用改 |
| 基线 | **R 的滑动均值**（不学 V） | 95% 的局都赢 ⇒ R 方差小 ⇒ 够用；少一处能出错的地方 |
| 折扣 γ | **1（不打折）** | 有限回合、无时间价值；与现状一致 |
| 数据 | **只用刚打完的那批** | on-policy 是 PG 的定义；用 buffer 就要重要性采样 |
| ε | **换成熵** | 采样本身就是探索；同时保留 ε 会让"探索"有两个来源、分不清谁在起作用 |
| 熵退火 | **不做**（v1） | 一次只改一件事（本仓库吃过"两件事一起改"的亏） |
| 重要性采样 | **不做** | staleness 用"调小广播间隔"压到 200 局；这是**已知的近似** |
| 是否保留 DMC 通路 | **保留**，`--algo {dmc,pg}`，**默认 dmc** | A/B 的对照臂就是老代码（两臂只能差一个变量） |

## 5. 成本（**必须先量再定预算**）

| 项 | 量级 | 依据 |
|---|---|---|
| 训练步前向 | **约 10× 行数** ⇒ **−33% 吞吐** | `log π(a\|s)` 要对**全部候选**算 logits；这个形态路线②实测过（51.7 → 34.6 局/秒） |
| 跨进程广播 | 每 200 局 7.8 MB ⇒ 约 35 MB/s 本机 IPC | §3.4（PG 臂把广播间隔从 1000 调到 200） |
| replay 重放 | **只有单进程省得掉** | 见下面的⚠️ |

⚠️ **自检改掉的一处**：我原来写「不用 buffer ⇒ 省掉重放」是**错的**。
多进程那条路里 worker **只发紧凑记录**（不发决策点）⇒ learner 侧**照样要重放**
（每步 32 局 ×18ms）。而 **A/B 用的就是 `--workers 2`** ⇒ **这一项省不下来** ✗。
只有单进程 `train()` 能用现场抓的那批（`fresh`）省掉重放。

⇒ 净成本就是那 **10× 前向**（≈ **−33%**，与路线②实测同一形态），
**不是"两下相抵"**。而且这个数字**要实测**（`tools/bench_train.py`，每档跑足 3 分钟 ——
短跑会把 spawn+import torch 摊进去，这个坑踩过）。
**量完再按预登记的档位定预算**（与路线②同一张表：≥70% 各 9000 秒；40~70% 等局数配对；<40% 停下讨论）。

## 6. 风险与守门

| 风险 | 应对 |
|---|---|
| **熵塌**（策略变成确定性的 argmax ⇒ 白换框架） | **守门**：每个训练步算熵；低于**候选数对应的均匀熵的 5%** 就**响亮地 raise**（本仓库纪律：失败必须响）。日志每 N 步打一次熵 |
| **logits 发散**（`\|z\|` 爆炸 ⇒ 策略退化成 one-hot + 数值不稳） | 复用 `check_q_scale` 的口径守 `\|z\|`（阈值另定，标签尺度还是 ±3） |
| **方差太大**（REINFORCE 的经典毛病 ⇒ 学不动） | 基线（§3.2）+ 熵项；训练曲线盯 loss 的抖动；**判据 1 是主判据，学不动就是学不动** |
| **staleness 偏差**（worker 的数据是旧策略的） | 间隔压到 200 局（§3.4）；**已知近似，写在明面上** |
| **赢了新尺子、输了老尺子** | 判据 2 守门（`vs 贪心` 不掉） |
| 热启动的 Q 权重让初始策略太尖 | 监控熵**初值**；熵项会自己调 |
| 成本被低估 | §5：先量再定预算 |
| 真机证据拿不到 | 只认离线判据，结论里写明「没有真机证据」 |

## 8. 单元测试（都要能脱离牌局跑）

1. **机制测试（最重要，但**我第一版把它写错了**）**：

   我原来写"`β_ent=0` 时未选中候选的 logit 梯度必须是 0"—— **错的**：
   `∇ log π(a)` 对 `z_j`（j≠a）是 `−π_j`，**非零**（那是 softmax 的归一化项，躲不掉）。

   **真正该钉的性质是「对比」**：设 `R > b`，则
   - **被选中那一手**的 `z` 的梯度方向是**往上**（`+`）
   - **未被选中的候选**的 `z` 的梯度方向是**往下**（`−`）

   而**回归**做不到这一点：所有候选的目标都是同一个 `R` ⇒ 所有梯度**同号**
   ⇒ 没有对比 ⇒ 这正是"标签不区分动作"的数学形态 ✓

   所以这条测试是：玩具网络 + 数值验证 → **选中项与非选中项的梯度符号相反**（`R > b` 时）。
   这条同时也解释了为什么路线②会失败（它同样是往所有候选拉同一个目标）。
2. `--algo dmc`（**默认**）时逐点等于现在 —— 默认行为不变。
3. 熵守门：人为把 logits 放大到退化 ⇒ 必须 raise。
4. `log π(a|s)` 的数值正确性：与手算的 softmax 一致（含候选不等长、含「过」）。
5. `--init 1407` 之后，**PG 路径的 argmax 与老的 `q_values` argmax 逐点一致**
   （决策路径不变 ⇒ 面板/影子/评测器都不用改）。

## 9. 不在范围内

- **PPO 的 clip / 多轮更新** —— v1 只做纯 REINFORCE（一步一更新）。先证明方向，
  再谈工程优化；PPO 是"如果 REINFORCE 有效"的下一步
- **学 V 网络当基线** —— v1 用 R 的滑动均值（§3.2）
- **熵退火**（§3.3）
- **重要性采样 / off-policy 修正**（§3.4）
- 改状态/动作编码 —— 另一个方向（状态编码里**没有「台面这手是谁出的」**，
  网络得自己从 432 维反推；人类看牌第一眼就看这个）。**它会作废所有 checkpoint**，
  所以是独立的一轮，不混进来
- 动对手（`--opp-kind` 保持 `greedy`，与对照臂对齐）
- 真机自动打牌（项目红线）
