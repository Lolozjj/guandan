# 多进程自对弈 —— 设计

> 2026-09-26。用户批准的方向：**先用多进程把 20 个核用起来**，Rust 内核留到以后再议。
> 前置阅读：`docs/superpowers/plans/2026-09-25-plan3-training-delivery.md`（训练循环）、
> `docs/superpowers/plans/2026-09-25-shadow-delivery.md`（本轮的其他发现）。

## 1. 目标与成功判据

**目标**：同样墙钟时间里多学一点 —— 把单进程训练循环（**13.2 局/秒**）改成
「N 个 worker 进程打牌 + 主进程学习」。

**成功判据（按顺序）**：

1. **吞吐**：worker 数 1/2/3/4/6 各量一次，报出曲线与**瓶颈落在谁身上**。
   预期（按剖面推算，见第 2 节）**约 23 局/秒**，即 **1.8×**；学习进程若改走 GPU 另测。
2. **等价性**：同一种子下，worker 产出的局与在进程内跑 `generate_batch`
   **逐局逐位一致**（`GameRecord` 的 level/first/hands/actions 全等）。
3. **训练可用**：短跑（10 分钟）loss 正常下降，`vs 贪心` 与单进程同量级。
4. 判据与指标不变：退出码仍是 `vs 贪心 ≥55%`；收尾仍打印**炸弹浪费率**。
5. **单进程那条路保留**：`--workers 1` 即老行为（测试、可复现、小机器用）。

## 2. 已确认的事实（都带实测证据，别重新推）

- **瓶颈是单线程 Python，不是算力**：25 秒训练的剖面（tottime）里
  `cards.slot` 2.31s（560 万次）、`Tensor.to` 1.42s、`encode_state` 1.37s、
  `cards.is_card` 1.06s、`encode_action` 0.99s、`encode_history` 0.92s，
  而 **torch 前向只占 16%**（linear 1.52s + lstm 1.05s）。
  所以：`--batch` 调大几乎没用、加线程没用（GIL）—— **要么多进程，要么换语言**。
- **2026-09-26 已顺手做掉两处**：`is_card`/`slot` 改查表（412ns→91ns、186ns→88ns，
  这两条原占 13% → 约 3.6%）；ε 改成**按局数**退火（原来按时间退，9 小时预算下
  第 25 分钟 ε 还有 0.96，大半时间在做随机探索 —— 上一轮「加时长收益变小」的真因）。
- **跨进程要传的东西有现成的紧凑形式**：`train/replay.py` 的 `GameRecord`
  = `level + first + hands(4×27) + actions(每步候选下标)`，**几百字节/局**；
  `replay.expand(rec)` 能重放回全部决策点（约 **27 ms/局**）。
  ⚠️ 因此**不要**传编码后的张量：一局约 1.6 MB，100 局/秒就是 160 MB/s（方案 B，已否）。
- **学习进程的天花板**（按 27ms 重放 + 一次 32 局的训练步推算）：
  约 23~26 局/秒 —— **这就是方案 A 的上限**，再多 worker 只会堆队列。
  想再往上，下一步是让学习进程走 GPU（本轮只**量**，不默认切）。

## 3. 架构

```
   ┌────────────┐  GameRecord×32 + ranks   ┌──────────────────────────┐
   │ worker 0   │ ───────────────────────▶ │ learner（主进程）         │
   │ worker 1   │                          │  收 → buffer.add          │
   │ …          │ ◀─────────────────────── │  → 采样 → 训练            │
   │ worker N-1 │   (state_dict, eps)      │  → 每 M 局广播权重        │
   └────────────┘                          │  评测 / 存档 / 日志（原样）│
                                           └──────────────────────────┘
```

**worker**（`train/worker.py`）：

- 循环：**照用 `train/selfplay.generate_batch`**（含混入对手、ε、只记学习那一队），
  每批 `BATCH_GAMES` 局打完后把 `[(GameRecord, ranks), …]` 经队列发回。
  `ranks` 是局末名次 —— 学习侧要拿它算 reward（`rules.reward`），重放时不再重算。
- 每批之间**非阻塞**看一眼控制队列：收到 `(state_dict, eps)` 就 `load_state_dict`
  + 更新 ε（**策略保鲜**；replay buffer 本来就允许陈旧，所以频率不必高）。
- 每个 worker 一个种子（`seed = base + k`）→ 局与局之间不重复。

**learner**（`train/selfplay.py::train_parallel`）：

- 收记录 → `buf.add(rec)` → 采样 → `replay.expand` → 训练一步（这一套**原样复用**）。
- 每 `WEIGHT_SYNC_GAMES` 局（初值 1000）把 `net.state_dict()` + 当前 ε 广播给所有 worker。
- 评测 / 存权重 / 打印 / 退出码：**与单进程那条路共用同一份代码**。
- **worker 死了必须炸出来**（`Process.is_alive()` 每轮查）—— 不许静默降速。
  这是本仓库的纪律（「失败必须响」，spec §6⑥）。

**配置**：`--workers N`（默认 1 = 老行为）。默认推荐值在验收里量出来再定
（按天花板推算，**3~4 个**就够填满 23 局/秒；多给的只会堆队列）。

## 4. 关键取舍

| 取舍 | 选择 | 为什么 |
|---|---|---|
| worker 送什么 | **紧凑 GameRecord**，学习侧重放 | 每局几百字节；张量方案 IPC 会爆（1.6 MB×100/s）。重放循环只有一份 |
| 权重保鲜怎么做 | 定期广播 `state_dict` + ε | 不广播的话 worker 永远用开局那版策略，学的和打的两回事 |
| ε 谁来定 | **learner 按全局局数算**再广播 | 各 worker 自己数会各自退火（每个都以为自己是全部） |
| 单进程还留不留 | **留** | 测试要可复现；小机器/调试要能跑；等价性验收要拿它当参照 |
| worker 数默认 | 1（显式开） | 默认行为不变，避免悄悄改变已有跑法的语义与内存占用 |
| 学习进程用不用 GPU | 本轮**只量** | 之前实测 GPU 在「Python 为主的循环」里更慢；分工后 torch 占比上升，值得重测，但先别默认切 |

## 5. 验收

1. **等价性**（`tests/test_worker_equivalence.py`）：同一种子/同一版本权重下，
   worker 产生的 8 局与进程内 `generate_batch` 的 8 局 `GameRecord` **全等**。
2. **吞吐曲线**（`tools/bench_train.py`）：worker 数 1/2/3/4/6 各跑 60 秒，
   打印局/秒 + 队列积压 + 学习进程利用率；报出瓶颈在哪一环。
3. **短跑**（10 分钟，2~3 worker）：loss 正常下降；结尾 `vs 贪心` 与单进程同量级；
   `炸弹浪费率` 照样打印。
4. **worker 死亡**：人为 kill 一个 worker，训练必须**报错退出**（不许静默变慢）——
   写成测试。
5. `--workers 1` 跑一遍，与改动前的日志逐行同形（看不出区别）。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| Windows 用 spawn，import 不安全会炸 | worker 入口写成 `if __name__ == "__main__"` 保护；测试里真起一次 |
| 队列积压把内存吃光 | 队列设 `maxsize`；learner 满了先取后放；积压写进日志 |
| 权重广播成了新瓶颈（7.8 MB × N） | 每 1000 局才广播一次；实测这一项的开销并打印 |
| worker 数给多了反而慢 | 验收②的曲线选点；文档写明推荐值 |
| 结果不可复现（多进程调度） | 等价性只保证「同种子同权重同批大小」，不承诺跨进程调度的逐位复现 —— 这一点写进文档 |

## 7. 不在范围内

- Rust/C++ 内核（用户已同意留到以后；按剖面推算只值 2.4×）
- 学习进程的 GPU 落地（本轮只量；量完给结论）
- 分布式（多机）
- 把 replay buffer 换成共享内存（先看队列够不够）
