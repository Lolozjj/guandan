# 换目标：动作计价（炸弹代价）—— 设计

> 2026-09-27。用户批准的方向：**先给「用炸弹」挂一个挂在动作上的代价**（路线①），
> 不够再上 n 步自举（路线②）。
> 前置阅读：`docs/superpowers/plans/2026-09-27-opponent-pool-delivery.md`（池子被证否的那一轮）、
> `docs/superpowers/specs/2026-09-27-current-scheme.md` §四（训练思路）。

## 1. 目标与成功判据

**要治的病**：模型「有普通牌能压却出炸」（用户实机报的，2026-09-26）。
试过两条路都没治：混入固定对手（0940）、对手池 league+PFSP（R2 复跑）。
`bomb_waste` **面对贪心**三版权重各量一次是 **4.2% / 5.1% / 5.1%**（0033 / 0940 / 1407），
R2 两臂**对池成员**是 **4.9% / 5.2%** —— 没有一次是可分辨的改善（差都不到 1 个标准差）。

**这一轮的诊断（收窄后）**：问题**不在对手**，在**信用分配**。

- 一局 **~132 个决策点共享同一个标签**（±1/±2/±3）⇒ 网络只好去学「从这个局面
  能拿几分」——那是个**状态值**；动作那一维只剩残差。
- 实测印证（2026-09-27）：候选间离散度中位 **0.401**，而**首选与次选之差中位只有
  0.123**，标签尺度却是 **±3**。动作通道能分到的信号只有百分之几。
- **池子那一轮给了反证**：池子臂里学习者对池成员的胜率是 **38~58%**
  （真正的五五开，标签有对比），**照样没进步**。
  ⇒ 「对手不够强」被排除，问题在目标本身。

**目标**：让标签里出现**挂在动作上的**成分，从而造出「炸 vs 不炸」的对比。

### 成功判据（按顺序）

1. **`bomb_waste`（面对贪心）下降 ≥1 个标准差** —— 这是主判据，
   而且这个阈值是**预登记**的（不要事后改）。
2. **`vs 贪心` 不许掉 ≥1 个标准差** —— 判据本身是「代价有没有扭曲策略」的守门人。
3. **「用炸率」不许塌** —— 见 §5.3。**一条挂代价的最典型失败是矫枉过正：
   模型从此一刀切不炸。** 那不比乱炸好，而且用户会觉得建议变蠢。
4. **真机影子日志同向** —— `net/shadow.jsonl` 是唯一来自真实对局的证据
   （用户的抱怨就是从那儿来的）。**需要用户打几局**。
5. **杀停**：1 或 2 任一不满足 ⇒ **判定这个 λ 不行**（调小或放弃），
   按预登记转路线②（n 步自举）。**不要靠调大 λ 硬凑。**

## 2. 已确认的事实（都带证据，别重新推导）

- **奖励口径**：零和、从出牌人视角，`±points`，`points` 只看赢家队的**最差名次**
  —— 双上 3 / 1、3 名 2 / 1、4 名 1。`MULTIPLIER = 1.0`（不带倍数，2026-09-25 实测
  推翻了「打炸弹抬倍数」那个前提）。
- **动作通道确实在工作**，但边际很薄：离散度中位 0.401、首选次选之差中位 0.123
  （2026-09-27，144 万局那版 vs 随机初始化对照：后者 100% 打平）。
- **炸弹判定已有现成函数**：`Meld.is_bomb`（`train/eval.py::bomb_waste` 在用）。
  不需要新造牌型判断。
- **标签有两个产地**：`generate_batch` 的现场抓取（`caps`）与
  `replay.expand` 的重放。**必须共用同一个实现** —— 两份会漂，而漂了的后果是
  「刚打的那批」与「从 buffer 里取的」学到两个不同的目标，**且静默**
  （本仓库为「副本会漂」反复吃过亏）。
- **池子被证否**（2026-09-27 R2 复跑）：同局数 24 万，池子臂 `bomb_waste` 对池中位
  **5.2%** vs 对照臂 **4.9%**（0.4 个标准差 = 没差别）；而池子臂**每小时少跑 39% 的局**。
  ⇒ **本轮不碰对手**，`--pfsp` 保持关闭。
- **从强存档出发训练会退**：修好 ε 之后两臂仍是 95.2% → 93~94%（同尺子）。
  所以本轮 A/B **两臂都必须从同一个存档热启动**，只差 λ 一个变量。

## 3. 架构

### 3.1 标签怎么变

```
现在：  y_t = R                       （终局 ±分，一局内所有决策点相同）
改成：  y_t = R − λ · B_t             （B_t = 从这一步起，**该座位自己**用掉的炸弹数）
```

- **`B_t` 含第 t 步本身** —— 这是 reward-to-go 的口径：逐步代价 `r_k = −λ·[a_k 是炸弹]`，
  标签 = 未来所有 `r` 之和 + 终局回报，所以 `B_t = Σ_{k≥t, seat_k = seat_t} [a_k 是炸弹]`。
- **只管该座位自己的炸弹**：奖励本来就是「出牌人视角」的零和量，代价用同一视角才自洽
  （四个座位共享一套权重，所以每家都按自己的炸弹计价 —— 对称）。
- **带 `B_t` 的「未来」那一截在一局内共享**，只有 `[a_t 是炸弹]` 那一项是**逐动作**的
  —— 那正是要造出来的对比。

### 3.2 唯一的实现（不许两份）

`train/replay.py` 加一个纯函数，**现场与重放都调它**：

```python
def mc_targets(seat_meld, ranks, learn=None, bomb_cost=0.0):
    """被保留的那些决策点的 DMC 标签 —— **现场与重放共用的唯一实现**。

    `seat_meld`：这一局**全部**步骤的 `(出牌座位, Meld 或 None)`（过牌是 None）——
    **全量进来**，因为 `B_t` 要沿着一局往后数；过滤（`learn`）**在函数里面做**，
    别让调用方各写一份（那正是「副本会漂」的入口）。
    返回 `(labels, bombs)`；`bombs` 是这一局的炸弹总手数（验收的「用炸率」用，
    **λ=0 时也返回** —— 对照臂同样要有这个数）。
    """
```

调用点：

- `generate_batch` 的收尾：把 `caps` 的座位 + `acts[i]` 的 Meld 拼成 `seat_meld`
- `replay.expand`：本来就在逐步枚举 `acts`，直接拼

⚠️ **两处都改成调它**，并且**留一条测试比对两条路的产出逐点相等**
（`opp_mix=1.0` 下，现场 vs 重放，标签必须一模一样）。

### 3.3 λ 怎么配

`λ` 是这一轮**唯一的旋钮**。标定依据：

| 参照量 | 值 | 含义 |
|---|---|---|
| 标签尺度 | ±1 ~ ±3 | 一次双上 3 分 |
| 首选与次选之差（中位） | **0.123** | 动作边际 |
| 候选间离散度（中位） | 0.401 | 动作通道的总量程 |

- `λ` 与**动作边际 0.123** 同量级时，代价足以翻转「本来就在打平」的那部分决策；
- `λ` 与**标签尺度 3** 同量级时，代价会压过胜负本身 —— 那是矫枉过正区。

**初值 `λ = 0.2`**（≈1.6 倍动作边际、约 7% 的标签尺度）。**按实测调，要动就动这一个数。**
CLI：`--bomb-cost F`（默认 `0.0` = 现在的行为，**默认不变**）。

### 3.4 一处纪律：代价只在学习那一队的决策点上

`learn` 过滤（2026-09-27 已修的那个）之后才计价 —— 固定对手的着法本来就不进训练目标，
更不该被计价。**顺序是：先按 `learn` 过滤，再算标签。**

## 4. 关键取舍

| 取舍 | 选择 | 为什么 |
|---|---|---|
| 代价挂在动作上还是状态上 | **动作上** | 挂在状态上的（势函数成形）在 MC 里会望远镜化成状态基线，**造不出动作间对比**（§1 的算术）。这是这条路线的全部意义 |
| 代价算谁的炸弹 | **该座位自己的** | 奖励是出牌人视角的零和量，代价要同一视角才自洽 |
| 含不含未来 | **含**（reward-to-go） | 与 DMC「未来回报之和」的口径一致；只有第 t 步那一项是逐动作对比 |
| λ 默认值 | **0.0（关）** | 默认行为不变（与 `--workers 1` / `--pfsp` 同一个原则） |
| 要不要动对手 | **不动** | 池子已被证否；本轮只差 λ 一个变量 |
| 要不要自举 | **不要** | 那是路线②，是这一轮的兜底，不是同时上的东西 |

## 5. 验收

### 5.1 A/B（主判据）

**两臂都从同一个存档热启动**（`runs/rl/20260926-1407/best.pt`）、同种子、
同秒数预算、`--pfsp` 关、其余全同：

- **对照臂**：`--bomb-cost 0.0`
- **处理臂**：`--bomb-cost 0.2`

⚠️ **同秒数 ≈ 同局数，因为两臂都不开池子、速率相同**（池子那一轮的 39% 吞吐税
这一轮不存在）。但仍然**用 `--snap-every` 的快照做同局数配对**再比一次 ——
万一速率有偏差，配对是免费的保险（`tools/ab_compare.py` 的用法）。
训练循环是按**秒**限的，没有「按局数停」的开关；本题不需要为它加。

### 5.2 同一把尺子（`tools/ab_compare.py`）

- `vs 贪心`（400 局、`seed=1002`）与 `vs 随机`
- `bomb_waste` **两个数都要**（自对弈 / 面对贪心 —— docstring 自己警告过）
- 三臂（含起点 1407）放在同一批牌、同一组对手上

### 5.3 ⭐ 新增：「用炸率」—— 防止矫枉过正

**挂代价最典型的失败不是没效果，是「从此舍不得炸」。** 那不比乱炸好，
而且用户看面板会觉得建议变蠢。所以要同时量：

| 指标 | 怎么来 | 看什么 |
|---|---|---|
| `bomb_waste` | 已有（浪费数 / 能出普通牌的机会数） | **要降** |
| **用炸率** | `mc_targets` 顺手返回的 `bombs` ÷ 局数 | **不许塌**（掉到对照臂的一半以下就是矫枉过正） |
| **浪费占比** | 浪费数 ÷ 总炸数 | 比「浪费率」更贴近「白炸的比例」 |

`bomb_waste` 只回答「有得选的时候选错了吗」，回答不了「还炸不炸」——
两者一起看才完整。

### 5.4 真机（唯一来自真实对局的证据）

训练完之后**请用户打几局**，读 `net/shadow.jsonl`：按 `session` 行切分（**它是追加累积的文件**）、
按 `(session, deal, pos)` 去重、用 `net/sim/meld.py::legal_moves` **真枚举候选**，
比「模型首选是炸弹」与「本来能用普通牌压」的比例。**用户最初的抱怨就是从这儿来的，所以也只有这儿能结案。**

### 5.5 单元测试

1. `mc_targets`：`λ=0` 时与现在的标签**逐点相等**（默认行为不变）
2. `mc_targets`：`λ>0` 时，出炸那一步的标签比不出炸**低 λ**（逐点对比）
3. `mc_targets`：`B_t` 只数**该座位自己**的炸弹（夹一个对手出炸的局面）
4. **现场与重放逐点相等**（`opp_mix=1.0`，λ>0）—— §3.2 那条纪律
5. `--bomb-cost` 默认 0.0，且 **`λ=0` 时生成的局与改动前逐局相等**（同种子）——
   「默认行为不变」要用可测的口径说（参照 `tests/test_worker.py` 那条逐局比对）

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| **矫枉过正**（从此不炸） | §5.3 的用炸率 + `vs 贪心` 双守门；杀停条件 |
| **扭曲策略**（代价移动了最优解） | 这是路线①的**已知代价**（势函数定理在这里不适用，因为代价挂在动作上、不是势函数）。所以判据是 `vs 贪心` 不许掉 —— 它就是这个风险的守门人 |
| **两份实现漂** | §3.2：只写一个 `mc_targets`，两条路都调它，并有逐点相等的测试 |
| λ 太难调 | 只暴露一个数 + 预登记杀停；不靠调大 λ 硬凑 |
| 代价与「赢」的量级不匹配 | λ 的标定依据写在 §3.3（动作边际 0.123 / 标签尺度 3），不是拍脑袋 |
| 真机证据拿不到（用户没空打） | 那就**只认离线两个判据**，并在结论里写明「没有真机证据」—— 不许把离线数说成已经治好 |

## 7. 不在范围内

- **n 步自举 / TD(λ)**（路线②）—— 这一轮的兜底，**不同时上**。
  理由：两件事一起改，出了效果分不清是谁的功劳（池子那一轮刚吃过这个教训）
- actor-critic / PPO（路线④）
- 势函数基线（路线③）—— 按 §1 的算术它造不出动作间的对比，**预期治不了本**
- 动对手（池子已证否）、动网络结构、动状态/动作编码、动判据阈值
- 真机自动打牌（项目红线）

## 8. 需要定的初值

| 常量 | 初值 | 依据 |
|---|---|---|
| `BOMB_COST`（λ） | **0.2** | ≈1.6 倍动作边际（0.123）、≈7% 的标签尺度（3）。**唯一的旋钮，按实测调** |
| A/B 的时长预算 | 各 9000 秒（≈25 万局） | 与 R2 复跑可比（池子臂那一轮正好 25.9 万局）；两臂都不开池子，速率相同 |
| `--eps-games` | 200000 | 与 R2 复跑同（两臂都要一样） |
| 杀停阈值 | 1 个标准差 | 预登记，不许事后改 |
