# 对手池（league + PFSP）—— 设计

> 2026-09-27。用户批准的方向：**把固定对手从「贪心」换成模型自己的历史版本池**。
> 前置阅读：`docs/superpowers/specs/2026-09-27-current-scheme.md`（现用全图）、
> `docs/superpowers/specs/2026-09-24-guandan-rl-advisor-design.md` §5（DMC 训练）。
>
> **本轮边界（用户 2026-09-27 定）：先修 `expand` 污染，再做池子。** 分两期，改一项验一项。

## 1. 目标与成功判据

**要治的病**：模型「有普通牌能压却出炸」（用户实机报的）。2026-09-27 的诊断：
不是没被惩罚，是**惩罚的信噪比太低**。

训练标签是整手牌的最终得分（±1~3）。而现在的对手是贪心，**95% 的局都赢**
⇒ 标签里 95% 是「+3」，「炸 vs 不炸」的区别全挤在那 5% 里。
`opp_mix=0.5 / greedy_share=0.8` 的实际含义是：**一半算力花在一个已经打穿的对手身上**。

**目标**：换掉那把尺子 —— 让错误真的会输掉牌局，标签里重新有区分度。

**成功判据（按顺序）**：

1. **`bomb_waste` 对池子成员下降**（这是真正的判据）。
   `bomb_waste` 一次只吃**一个**对手，所以要**对池子的若干代表成员分别量**
   （取中位或均值），同时保留对贪心那个数（保与历史可比）。
   ⚠️ **不要只看对贪心的那个数** —— 贪心那把尺子已经饱和（95.2%），对它的数不会动。
2. **判据（退出码）不变**：仍是 `vs 贪心 ≥ 55%`。**这条不许动** ——
   它保住与历史所有跑（0033 / 0940 / 1407）的可比性。
3. **吞吐不塌**：换成网对手之后局/秒要与现在同量级（实测，不靠估）。
4. **池子健康度可观测**：每个成员的胜率与采样权重落下盘；
   池子塌成一个成员必须**能看出来并且响**（本仓库纪律：失败必须响）。
5. **杀停条件**：A/B 里池子臂的 `bomb_waste`（对池子成员）**不比对照臂低 1 个标准差以上**
   就停 —— 那说明病根不在对手，在蒙特卡洛标签本身。下一步是换目标（信用分配），不是加算力。

## 2. 已确认的事实（都带实测证据，别重新推导）

- **DMC 三件套齐**（2026-09-27 实测）：目标 = 整手牌终局回报、不做 bootstrap；
  `QNet(state, action, hist) → 标量`；决策时对**每个候选**打分取最大。
  **动作通道真的在起作用**：训练后候选间离散度中位 **0.401**，
  随机初始化的同结构网络是 **0.000**（100% 打平）。
- **边际很薄**：首选与次选之差中位 **0.123**，而标签尺度是 **±1~3**
  —— 边际常只有结果尺度的 4~12%；5.7% 的局面首选次选几乎打平。
  **这正是「换对手」要改善的东西**：对手强了，标签才有区分度。
- **`replay.expand` 会把固定对手的着法当训练目标**（真 bug）：
  `opp_mix=0.5` 时 6008 个重放训练点里 **1040 个（17.3%）是固定对手的着法**，
  标签却是那一局的胜负。`train_parallel` **永远**走 `expand`，起步就是这个污染率。
  ⚠️ **池子会放大它**：池子里的对手是**强模型**，拿它们的着法当训练目标，
  性质从「拿一个弱基线当老师」变成「**蒸馏一个强策略**」。所以拿它当前置。
- **权重只在「刷新最好」时存**：1407 那 144 万局只落了几个点，
  所以**池子原料不够**，得加定期快照。
- **现有 5 个存档强度是分层的**（`runs/rl/*/best.pt`，自报 vs 贪心）：
  0843 = 55.5%（1 万局）· 2115 = 79.5%（4 万）· 0940 = 90.0%（18 万）·
  0033 = 91.0%（20 万）· 1407 = 96.0%（144 万）。
  而 1407 打 0033 实测 **62.3%** —— 这正是 PFSP 要的那种数。
- **跨进程的记录里带不了「用了哪个对手」，而这正是 PFSP 必需的**：
  `GameRecord` 只有 `level/first/hands/actions`。**要加一个 `opp` 字段**（见 §3.2）。
- ⚠️ **「胜者不用加」这句话被实测推翻了**（2026-09-27 写代码时）：
  原设计以为 `expand` 重放出来的 `y` 符号就够用。实测**重放一局 18.3 ms**，
  而学习进程每秒要处理几十局池对局 —— 光为了读一个正负号就多花几十个百分点。
  所以 `GameRecord` 也存了 `won`（一个 bool，8 字节）。**一个 bool 换掉 18 ms。**
- **worker 现在是「32 局同步推进 + 一次批量前向」**。一旦不同局的对手是不同权重，
  固定对手那一路就不能再是便宜的 Python 调用 —— 见 §3.3。
- **面板按修改时间挑 `runs/rl/*/best.pt`**（`net/advise.py::newest_weights`）。
  ⇒ 快照**不能**叫 `best.pt`，也不能放在会被这个 glob 命中的位置。

## 3. 架构

### 3.0 第 0 期（前置）：修 `expand` 污染

`GameRecord` 加一个字段：

```python
@dataclass(frozen=True)
class GameRecord:
    level: int
    first: int
    hands: tuple
    actions: tuple
    learn: tuple = None      # 学习座位；None = 四家都学（纯自对弈 / 老记录）
```

- `expand(rec)` 按 `rec.learn` **过滤决策点**（None ⇒ 不过滤 = 老行为）
- `generate_batch` 建记录时传 `learn=learn[k]`
- 留一行开关 `--learn-all-seats` 可回退到老行为，**留作对照**

**为什么不改成「只存学习那一队的步骤」**：重放需要**全部**步骤才能走下去
（`_fixed_pick` 也要靠它推进局面）。过滤必须发生在产出训练点那一步。

### 3.1 池子是什么

```
   种子池（5 个现有 best.pt）
        ＋
   训练中定期快照  snap_<games>.pt（每 2 万局，与「有没有进步」解耦）
        │
        └─► 只留最近 20 个（约 156 MB，放在 <run>/pool/ 下）
```

- 快照路径：`runs/rl/<run>/pool/snap_<games>.pt`
  **故意嵌套一层** —— `newest_weights()` glob 的是 `runs/rl/*/best.pt`，
  嵌套目录与 `snap_*` 名字都命不中，面板不会误加载。
- 每个成员一个整数 `id`（种子池从 0 起，新快照递增）。
- **当前权重不进池**（它就是学习者，自对弈那一半已经覆盖它了）。

### 3.2 PFSP：每次挑哪个对手

混合局（`opp_mix=0.5`）里怎么选对手：

```
   20%  → 贪心（固定保留份额，不走 PFSP）
   80%  → 池子，按下面加权采样
```

贪心保留的理由：①它是判据的尺子；②它便宜（走 Python 捷径，不花前向）；
③它是**防池子退化的锚**。

池子内部的采样权重（`p_i` = 学习者对成员 i 的胜率）：

```
   权重_i  ∝  0.8 × p_i·(1 − p_i)  +  0.2 × (1/K)
                └── 专挑五五开 ──┘      └─ 均匀下限 ─┘
```

- `p·(1−p)` 在 `p = 0.5` 取最大；`p → 0`（完全打不过）与 `p → 1`（完全打穿）
  **都趋 0** —— 前者没梯度、后者没信息。
- **均匀下限**给 20%：预热期、防饿死、以及胜率估计陈旧时的兜底。
- **预热**：某成员的局数 < `PFSP_MIN_GAMES`（初值 20）时，**把它的 `p` 当成中性的 0.5**
  —— 它一开始的 `p` 只是噪声。
  ⚠️ **不能给预热成员一个「特殊的大常数」**：`p(1−p)` 的最大值只有 **0.25**，
  给 `1.0` 就等于让它比健康成员重 4 倍，池子会一直扑向没测过的成员。
  （这条是写代码时被测试抓出来的，见实现计划 Task 3。）
- **胜率要滑窗**：学习者在变强，老胜率会过期。用最近 `PFSP_WINDOW`（初值 200）
  局的胜负计数，加 Beta 平滑 `(wins+a)/(games+a+b)`，初值 `a=b=2`。

**胜率从哪来**：每局结束，`expand` 的 `y` 符号 ⇒ 哪队赢；
配合这一局用的对手 `id` ⇒ 免费。

所以要给 `GameRecord` 再加一个字段（与 `learn` 同一个理由 —— 跨进程传的是它）：

```python
    opp: tuple = None        # 这一局的固定对手；None = 纯自对弈（两边都是自己）
                             # ("greedy",) / ("random",) / ("member", id)
```

worker 每打完一批就把它填上，learner 侧据此累计每个成员的胜负 —— **不用回传名次**。

### 3.3 worker 侧：按权重分组做批量前向

现在 `generate_batch` 把每个决策点二分：**学习队**（问当前网络）/
**固定对手**（`_fixed_pick`，便宜的 Python 调用）。

改成**三分**，并把「问网络」那部分按权重分组：

```
   每个在场局面 ──► 它这一步由谁出手？
                     ├─ 学习队        → 组「learner」（当前权重）
                     ├─ 池成员 m      → 组「member:m」
                     └─ 贪心 / 随机   → 便宜的 Python 路径（不占前向）
   每组各做一次批量前向，然后各自取 argmax
```

这是本改动**唯一的架构级改动**，也是干净的一般化：
「当前权重」只是众多组里的一组。**贪心/随机必须继续走便宜路径** ——
它们占混合局的 20%，白花前向会拖垮吞吐。

### 3.4 广播：增量发成员，别每次重发池子

worker 常驻持有池子（K × 7.8MB，K=20 时 156MB/worker）。控制通道三类消息：

| 消息 | 何时发 | 载荷 |
|---|---|---|
| `("member", (id, state_dict))` | **只在池子新增成员时**（每 2 万局一次） | ~7.8MB |
| `("weights", (learner_sd, eps, pfsp))` | 每 1000 局（沿用现有节奏） | ~7.8MB + K 个 float |
| `("stop", None)` | 退出 | — |

**为什么必须增量**：每次广播全池 = 20 × 7.8MB = 156MB，
按 1000 局（约 30 秒）一次算是 **5MB/s × worker 数** —— 直接把 learner 拖死。

### 3.5 `--init` 热启动（必须）

池子只有在模型足够强时才有意义。**没有热启动，验证池子得先练 9 小时。**

```
python -m train.selfplay 3600 --init runs/rl/20260926-1407/best.pt --workers 2 ...
```

`--init <checkpoint>` 载入权重后开训（跳过随机初始化）。它同时让
**A/B 可比**：两臂都从 1407 出发、同种子、同预算，只差有没有池子。

## 4. 关键取舍

| 取舍 | 选择 | 为什么 |
|---|---|---|
| 池子放什么 | 种子 5 个 + 每 2 万局一个快照，留 20 个 | 现有存档强度谱太稀（55%→96% 中间没档）；156MB 不痛 |
| 怎么采 | **PFSP**（`p(1−p)` + 20% 均匀下限） | 均匀会把一半对局浪费在早已打穿 / 完全打不过的成员上 |
| 贪心还留不留 | **留，固定 20%，不进 PFSP** | 它是判据的尺子；便宜；防池子退化 |
| 对手要不要 ε | **不要**（argmax） | 确定性 = 可复现；「这个存档的策略」就该是确定的 |
| 谁算 PFSP 权重 | **主进程算，广播给 worker** | 一处口径。各 worker 自己算会各自以为自己是全局 |
| 当前权重进不进池 | 不进 | 自对弈那一半已经覆盖它 |
| 集合边界 | 一期只修 `expand`，二期加池子 | 池子会放大 `expand` 污染；改一项验一项 |

## 5. 验收

**第 0 期（`expand`）**

1. RED→GREEN：`opp_mix=1.0` 时 `expand(rec)` 产出的座位集合 == **学习那一队**；
   `opp_mix=0.0` 时 == **四家**（老行为不变）。
2. 全套不许退步；`--learn-all-seats` 跑通可回退。

**第 1 期（池子）**

3. **PFSP 权重形状**（纯函数、可单测）：`p=0.5` 最大；`p→0` / `p→1` 趋小；
   预热期（局数 < `PFSP_MIN_GAMES`）按均匀；任何成员权重 ≥ 均匀下限。
4. **工程**：真起 worker 进程 —— 收到 `("member", …)` 后能用新成员出手；
   `--workers 1` 与改动前同形。
5. **健康度**：日志里有池子表（id / 局数 / 学习者胜率 / 采样权重）；
   有效成员数 `1/Σw²` 掉到 2 以下**必须响**。
6. **吞吐**：与现在同量级（实测每档跑足 3 分钟 —— 45 秒的短跑会把
   `spawn`+`import torch` 的启动成本摊进去，我们自己踩过）。
7. **A/B（真正的判据）**：从 1407 热启动，同种子同预算，
   一臂 `--pfsp`、一臂 `--learn-all-seats`+纯贪心（= 老行为）。
   ⚠️ **`--eps-games` 必须调小**，否则两臂都在近乎随机地探索，测不出差别。
   ⚠️ 评测的 `bomb_waste` **要对池子的若干代表成员分别量**（它一次只吃一个对手），
   对贪心那个数保留，但只作参考 —— 那把尺子已经饱和。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| **池子塌成一个成员**（循环训练、遗忘） | PFSP + 均匀下限 + 贪心固定份额 + 健康度上报（`1/Σw²` 报警） |
| **广播把 learner 拖死**（K×7.8MB） | **增量广播**：只发新增成员；采样权重单独小载荷 |
| **网对手拖慢吞吐** | 按权重分组做批量前向；贪心/随机保持便宜路径；实测吞吐 |
| 胜率估计陈旧 | 滑窗 + Beta 平滑 + 预热期均匀 |
| **不可复现**（采样依赖在线胜率） | 只保证「同种子 + 同池子状态」可复现，**写进文档**，别承诺更多 |
| 修完 `expand` 反而更差 | `--learn-all-seats` 一行回退，留作对照 |
| **病根不在对手** | §1.5 的杀停条件。无效就转「换目标（信用分配）」，不是加算力 |
| 池子成员的 `state_dict` 结构变过 | 加载失败**必须响**（不许静默少一个成员） |

## 7. 不在范围内

- MCTS / rollout（**DouZero 也没有**，它是纯值网络方法 —— 这不是缺件）
- reward shaping（显式的炸弹惩罚项）—— 那是另一根杠杆，单独议
- 改判据（`vs 贪心 ≥ 55%` 保住可比性）
- replay buffer 换共享内存；多机分布式
- 改 worker 架构之外的东西

## 8. 需要定的初值（都是起点，按实测调）

| 常量 | 初值 | 依据 |
|---|---|---|
| `SNAP_EVERY_GAMES` | 20 000 | 144 万局 ⇒ 约 70 个快照，留最近 20 |
| `POOL_SIZE` | 20 | 156 MB/worker |
| `PFSP_MIN_GAMES` | 20 | 少于这个数，`p` 是噪声 |
| `PFSP_WINDOW` | 200 | 最近 200 局的胜负计数 |
| `PFSP_UNIFORM` | 0.2 | 均匀下限 |
| `GREEDY_SHARE` | 0.2 | 混合局里贪心的固定份额（现在是 0.8，要降） |
| `opp_mix` | 0.5 | 沿用。**先别调** —— 混对手的局只训一个队，抬高会降低学习效率 |
